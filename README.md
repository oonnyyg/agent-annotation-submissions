
# tagsync — 离线标签同步工具（observed-remove set）

纯 Go 标准库实现。多个副本各自离线增删标签，通过交换本地 JSON 快照
收敛到同一结果。无网络服务、无自动历史压缩。

## 构建与运行

```sh
go build -o tagsync .
```

每个副本使用独立的状态文件；首次运行需用 `-replica` 指定固定唯一身份，
之后身份与新增编号从状态文件恢复，重启不复用旧标记：

```sh
tagsync -state replicaA.json -replica A   # 首次
tagsync -state replicaA.json              # 之后
```

程序从 stdin 读取 JSONL 命令（每行一个 JSON 对象），每条命令输出一行
JSON 响应，退出时持久化状态。

## 命令

| 命令 | 说明 |
| --- | --- |
| `{"op":"id"}` | 返回副本身份 |
| `{"op":"add","tag":"x"}` | 新增标签，返回新标记 `dot`（如 `A#3`） |
| `{"op":"remove","tag":"x"}` | 删除本副本已观察到的该标签全部新增标记 |
| `{"op":"list"}` | 列出当前可见标签（去重、排序） |
| `{"op":"explain","tag":"x"}` | 返回该标签的标记证据（live/removed） |
| `{"op":"export"}` | 导出快照 |
| `{"op":"merge","snapshot":{...}}` | 合并对方快照 |

## 删除语义（observed-remove）

- 每次 `add` 产生全局唯一标记 `dot = <replica>#<seq>`。同一标签重复新增
  会产生多个独立标记；可见列表按完整标签字符串去重。
- `remove` 只撤销**本副本当前已观察到**的该标签新增标记（生成删除证据/
  墓碑）。另一副本并发新增同名标签、其标记尚未被本副本观察到时，该次
  新增不受删除影响，合并后仍然可见——不存在"时间戳较新者覆盖全部历史"。
- 删除证据（墓碑）永久保留，不做垃圾清理；删除证据先于对应新增到达时，
  该新增到达后仍处于已删除状态，不会复活。

## 快照格式

`export` 返回的快照同时携带新增与删除证据：

```json
{
  "adds": {"tag-a": [{"replica": "A", "seq": 1}], "tag-b": [{"replica": "B", "seq": 2}]},
  "removed": [{"replica": "A", "seq": 1}]
}
```

- `adds`：标签 → 已知新增标记列表。
- `removed`：已被删除的新增标记列表。
- 标签可见 ⟺ 它至少有一个不在 `removed` 中的新增标记。

## 合并规则

- 合并 = 新增集合与删除集合分别取并集，因此**幂等**（重复投递不重复
  生效）且**与顺序无关**（任意合并顺序收敛到同一可见集合）。
- 合并旧快照不会回退本地进度（本地序列号只增不减，证据只增不删）。
- 以下情况**整次合并被拒绝**，本地状态不变：
  - JSON 格式错误或字段类型不符；
  - 同一标记（replica+seq）在快照中或与本副本已有记录对应到不同标签。

## 交换步骤

1. 副本 A：`{"op":"export"}`，把 `snapshot` 存入文件（如 U 盘）。
2. 副本 B：`{"op":"merge","snapshot":<A 的快照>}`，然后自己也 `export`。
3. 副本 A：`{"op":"merge","snapshot":<B 的快照>}`。

一轮交换后双方可见标签集合一致；可用 `explain` 查看每个标签背后的
live/removed 标记以定位冲突。

## 测试

```sh
go test ./...
```

覆盖：离线并发增删（并发新增在对方删除后仍保留）、乱序与重复合并收敛、
删除证据先到不复活、冲突标记整次拒绝、重启后身份与编号延续。
