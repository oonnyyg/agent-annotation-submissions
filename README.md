# 盘点工作台（stocktake-adjustment-desk）

仅用 Go 标准库实现的盘点工作台。所有事实以 JSONL 事件日志追加持久化在指定目录
（默认 `./data`，可用 `-dir` 或环境变量 `STOCKTAKE_DIR` 指定），重启后通过重放恢复状态。

## 运行

```sh
go run ./cmd/stocktake <命令> [-dir 数据目录] [参数]
go test ./...
```

## 命令

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `inbound` / `outbound` | `-loc -sku -qty` | 出入库；数量为非负整数，出库后不允许负库存 |
| `query` | `[-loc]` | 查询当前库存 |
| `take-start` | `-take -locs L [-locs L2]` | 开始盘点并冻结基线 |
| `count-record` | `-take -loc -rec -sku -qty` | 导入清点记录 |
| `count-void` | `-take -loc -rec` | 撤销未封存清点记录 |
| `count-complete` | `-take -loc` | 确认某库位清点完成 |
| `take-seal` | `-take` | 全部库位完成后封存，冻结差异明细 |
| `take-post` | `-take` | 差异入账，可重试，成功后幂等 |
| `take-reopen` | `-take` | 重开未入账盘点，保留记录与明细 |
| `take-show` | `-take` | 查看盘点状态、基线、记录与差异 |

## 冻结时点假设

- `take-start` 时对所选库位的账面数量做快照作为**基线**，此后所有实盘记录都表示
  这一冻结时点的数量。盘点期间的出入库只影响**当前库存**，不回写基线。
- 同一库位不能同时属于两个未结束（未入账）的盘点。
- 清点记录以 `(库位, 编号)` 唯一：同编号同内容重复导入幂等；内容冲突拒绝。
  不同编号的数量直接相加，系统**不按商品自动去重**。封存前可撤销记录。
- 每个库位必须显式 `count-complete`，全部完成后才能 `take-seal`。封存时按
  基线商品与实盘商品的并集计算 `实盘 - 基线` 差异；**未清点的基线商品按零实盘
  处理**（漏盘归零），差异明细随即冻结。
- `take-post` 把全部差异**加到当前库存**（不是用实盘量替换当前值）。任一商品
  将变负则整次拒绝，封存结果保留，可补足库存后重试；成功后再次入账只返回原结果。
  入账事件序号记录在盘点的 `post_seq` 中，配合 JSONL 日志可逐笔追溯调整依据。

## 各状态可用操作

| 状态 | 可用操作 |
| --- | --- |
| `open` | 出入库、导入/撤销清点、确认完成、封存 |
| `sealed` | 入账（可重试）、重开；不可再改清点 |
| `posted` | 仅查询与重复入账（返回原结果）；不可改清点或封存明细，不可重开 |

重开（`take-reopen`）仅对未入账盘点可用，回到 `open` 并保留全部清点记录与
封存明细，再次封存时会按当前记录重新计算差异。
