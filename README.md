# Lock Wait Replay — 锁管理模拟器

用于数据库故障演练的 Go 标准库锁管理模拟器。**不连接真实数据库**，通过顺序读取
JSONL 输入重现事务等待与死锁解除。同一输入回放必然得到相同输出。

## 运行

```sh
go run . -input events.jsonl   # 或省略 -input 从 stdin 读取
go test ./...
```

## 输入事件（每行一个 JSON）

| op | 字段 | 说明 |
| --- | --- | --- |
| `begin` | — | 开始事务，分配递增编号（编号不复用） |
| `commit` / `rollback` | `tx` | 结束事务并释放全部锁 |
| `lock` | `tx`, `resource`, `mode` | 申请锁，`mode` 为 `S`（共享）或 `X`（排他） |
| `status` | — | 输出当前状态快照（等待中事务也可执行） |

每个事件输出一行 JSON 结果：授予原因（`granted-immediately` / `already-held` /
`upgrade-immediate` / `granted-after-wait`）、`waiting` 标记、死锁报告
（`edges_before` 保留解除前的等待边、`cycle`、`victim`）或 `error`。

## 简化锁协议（重要）

这是**教学/演练用的简化协议**，与真实数据库（两阶段锁、锁表、超时、意向锁等）
不同，规则如下：

- 锁只有共享 `S` 与排他 `X`：共享可共存，排他与其他事务的任何锁冲突。
- 锁持有到事务结束；非等待事务重复申请已持有的同级或更弱锁直接成功。
- `S` 升 `X` 时保留原 `S` 锁排队等待，不把自己算作阻塞者。
- 每个事务最多一个待授予请求；等待中只能 `status` 或 `rollback`。
- 每个资源按请求顺序排队，禁止插队；释放后从队首依次授予，遇首个不可授予
  即停止，连续共享请求可一起获准。
- 等待图边指向冲突持有者与排在前面的等待者（无自环边）。每次状态变化后检测
  环，从环中事务选**开始最晚者**回滚，释放其全部锁并唤醒队列，重复直到无环。
- 非法操作（未知事务、非法模式、等待中加锁等）不留下任何锁或排队记录。
- 已结束事务不再出现于持锁与等待集合。

## 文件

- `lockmgr.go` — 锁管理器核心（授予、排队、等待图、死锁解除、快照）
- `events.go` — JSONL 事件处理与逐事件结果输出
- `main.go` — 命令行入口（文件或 stdin 回放）
- `lockmgr_test.go` / `replay_test.go` — 升级互锁、排队公平、多资源唤醒、
  回放确定性等测试
