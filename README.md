# sqlite-wal-snapshot

离线 SQLite WAL 核验器：逐帧验证 WAL 的有效前缀，区分**完整提交**与**尾部残留**，
并把可确认的最后一次提交重建为新的数据库页镜像。全程只使用 Go 标准库，
**不调用 SQLite 引擎，也不修改源文件**。

## 用法

```sh
go run ./cmd/walsnapshot -db main.db -wal main.db-wal [-out snapshot.db]
```

- `-db`：主库文件。**约定为该 WAL 产生之前、尚未回写其页面的基线镜像**。
- `-wal`：WAL 文件。
- `-out`：可选。快照输出路径。文件已存在或与任一源路径相同时拒绝写入。

报告以 JSON 输出到 stdout，包含：WAL 头信息（盐值、校验字节序）、逐帧记录
（偏移、页号、是否提交）、首个异常位置、被忽略的尾部字节范围、选定的最后
提交帧，以及快照每页的来源（`wal` 帧号或 `main`）。

## 核验规则

- 校验主库头（`SQLite format 3` 标识、页大小）与 WAL 头（魔数、版本
  3007000、页大小、头校验和），两者页大小必须一致。
- 支持规范定义的两种校验字节序（魔数 `0x377f0682` 小端 / `0x377f0683`
  大端），按魔数指示的字节序解释校验和字，**绝不使用主机字节序代替**。
- 从文件头开始连续核对每帧的盐值与累积校验和，帧页号必须非零。遇到坏帧
  或不完整尾帧立即停止，**不跳过错误继续接纳后面的帧**，并记录首个异常
  的字节偏移。
- 仅帧头中数据库页数非零的帧视为提交。取有效前缀中的**最后一次提交**；
  同一页被多次写入时，以该提交范围内的最后一帧为准；提交之后的帧即使
  校验正确也不进入快照。
- 快照按提交帧声明的页数截断或扩展。页面优先取所选 WAL 帧，否则取主库
  基线；基线缺页时报错，**不擅自补零**。
- WAL 有效前缀中没有提交帧时，快照为主库基线的原样副本，并在报告中以
  `noCommit` 与说明文字标明。WAL 头非法时只输出报告，不生成快照。

## 假设与限制

- **基线假设**：主库必须是该 WAL 产生前的状态。若主库已回写（checkpoint）
  过 WAL 中的页面，重建结果将不代表任何真实历史状态。
- 本工具只验证 WAL 文件自身的内部一致性（盐值、累积校验和、页大小），
  **无法证明该 WAL 与给定主库确实配对**——例如无法发现 WAL 属于另一个
  同页大小的数据库。
- 不解析 B-tree、空闲页等数据库逻辑结构，只做页镜像级重建。

## 测试

```sh
go test ./...
```

覆盖：两种校验字节序、同页重复写入（最后一帧生效）、提交后未提交尾部
排除、坏帧/坏盐值/不完整尾帧的前缀截断、缺页拒绝补零、无提交保留基线、
提交导致的数据库扩展与截断，以及输出路径保护。
