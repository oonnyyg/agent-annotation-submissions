# xml-record-splitter

一个用于数据交换流程的流式 XML 记录拆分工具。按给定的绝对节点路径从
大型 XML 文档中提取业务记录，每条记录输出为可独立解析的 XML 文件，
并保持原有的命名空间语义。

## 用法

```sh
go run . -path '{urn:orders}orders/{urn:orders}order' -in orders.xml -out batch-001 -max 1048576
```

- `-path`：从文档根开始的记录路径，每步为 `{命名空间URI}局部名`，
  无前缀的裸局部名表示"无命名空间"。不支持 `//` 等模糊后代搜索。
- `-in`：输入 XML 文件（UTF-8），缺省读标准输入。
- `-out`：新的批次输出目录，必须不存在（绝不覆盖已有目录）。
- `-max`：单条记录的字节上限，默认 16 MiB，超限明确失败。

输出目录包含 `record-000001.xml` …（按原文顺序编号）和 `index.txt`
（记录数量 + 每个文件的字节数与 SHA-256 摘要）。

## 匹配规则

- 流式读取（`encoding/xml` 的 `RawToken`），不把整份文档装入内存；
  每条记录单独缓冲并受 `-max` 限制。
- 路径逐步与元素栈精确比较 `{URI, 局部名}`；同名不同命名空间的元素
  严格区分。
- 记录按在原文中出现的顺序编号输出。

## 保真边界

保留的语义：

- 元素结构、字符数据（含 CDATA 转换后的文本）与属性值。
- 命名空间：脱离祖先后仍被使用的命名空间会在记录根上重新声明；
  默认命名空间与内部前缀重绑定都按解析后的 URI 处理；未带前缀的
  属性始终保持在"无命名空间"，不会错误继承默认命名空间。
- 记录根节点补齐继承自祖先的 `xml:lang` / `xml:space`，元素内部的
  覆盖关系保持不变。
- 注释与处理指令原样保留在记录内。

不保留的部分：

- 原始排版（缩进、空白）、原始前缀拼写与属性顺序。前缀按 `ns1…`
  重新生成，但重新解析后的 `{URI, 局部名}` 与文本语义完全一致。
- 属性值中自定义的 QName 文本不做语义解析（按普通字符串处理）。
- DTD / DOCTYPE 一律拒绝，外部实体不解析；未声明的前缀或实体、
  损坏的 XML 都会报错并给出字节偏移与行列位置。

## 发布语义

记录先写入输出目录旁的 `.staging-*` 临时目录，整份文档通过校验后
才发布为正式批次目录。文档尾部错误不会留下半批结果；`-out` 目录
已存在时直接失败，不会覆盖。

## 测试

```sh
go test ./...
```

覆盖跨层命名空间声明、前缀重绑定、默认命名空间与无前缀属性、
截断输入、未声明前缀/实体、DTD 拒绝、记录大小上限与发布流程。
