# Expiring Leave Bank

一个本地假期额度台账：按批次管理会过期的假期额度，解释每次请假
具体核销了哪几批额度，并保证撤销旧申请不会让已过期的额度重新
变得可用。全部数量使用整数分钟，仅依赖 Go 标准库。

## 运行

```sh
go run ./cmd/leavebank -dir <状态目录>
```

从标准输入读取 JSONL（每行一个操作），每个操作输出一行 JSON 结果，
状态持久化在 `<状态目录>/state.json`，重开程序后批次与申请状态保留。

## 操作

```json
{"op":"grant","date":"2026-01-01","batch":"B1","employee":"alice","start":"2026-01-01","end":"2026-04-01","minutes":4800}
{"op":"request","date":"2026-01-10","id":"R1","employee":"alice","minutes":240}
{"op":"cancel","date":"2026-01-20","id":"R1"}
{"op":"report","date":"2026-01-15","employee":"alice"}
{"op":"usage","id":"R1"}
```

- `grant` 发放一个额度批次，有效期为左闭右开 `[start, end)`。
- `request` 申请请假，返回冻结的逐批扣减明细。
- `cancel` 按原明细退回原批次，返回 `returns`（仍有效）与
  `expired`（已过期归还）两部分。
- `report` 查询余额：分别列出 `available`（可用）、`used`（已使用）、
  `pending`（未生效）、`lapsed`（到期未用）、`expiredReturned`
  （过期归还），并给出守恒校验 `balanced`。
- `usage` 查询某次申请的冻结扣减明细。

## 自定义额度规则

1. **整数分钟**：所有数量都是非负整数分钟，发放与申请必须为正数。
2. **左闭右开**：批次在 `start <= d < end` 的日期 `d` 上可用；
   到期日当天即不可用。
3. **日期只前进**：每个操作携带日期，只能非递减推进；到期判断完全
   由操作或查询日期决定，程序从不读取机器当前时间。
4. **只核销当日**：请假只核销操作当日有效的批次，不为未来日期
   预扣。扣减顺序为最早到期优先，同到期按批次编号字典序，允许
   跨批扣减；余额不足时整单拒绝，不留下部分扣款。
5. **幂等申请**：申请编号重复且内容（员工/日期/分钟数）完全相同时，
   优先于日期校验直接返回原结果，不推进日期、不重复扣减；内容不同
   则报冲突。申请成功后扣减明细即冻结，之后新增额度不会改变历史
   分摊。
6. **撤销回原批**：撤销严格按冻结明细退回原批次，不重新按当前顺序
   分配，且只能退一次。撤销时已到期的部分记为 `expiredReturned`
   （过期归还），永久不计入可用余额；仍有效的批次按退回后余额参与
   后续请假。
7. **总量守恒**：对每个批次与每位员工恒有
   `total = available + used + pending + lapsed + expiredReturned`，
   `report` 中的 `balanced` 字段实时核对这一等式。

## 测试

```sh
go test ./...
```

覆盖跨批申请、同到期字典序、余额不足整单拒绝、到期后撤销、重复
请求幂等与冲突、日期不可回退、半开区间与持久化重载。
