# zone-access-replay

园区门禁离线回放工具（纯 Go 标准库，不接入真实门禁设备）。根据区域容量、
人员初始位置、凭据配置与读卡事件，还原每个人员所在区域，并逐事件解释
允许/拒绝通行的原因。

## 用法

```sh
go run . -config examples/config.json -events examples/events.json \
    -at 2026-06-10T08:30:00Z
```

- `-config`：区域、人员、凭据、读卡器配置（JSON）。
- `-events`：事件文件（JSON），包含刷卡与人工纠正记录。
- `-at`：可选，RFC3339 UTC 时刻；输出该时刻全部事件处理后的区域名单。

输出依次为：逐事件判定（GRANT/DENY 及理由）、可选的时刻名单、最终占用汇总。

## 配置与事件格式

见 `examples/`。要点：

- 区域：`outdoor: true` 表示室外，不限人数；室内区域有 `capacity`。
- 凭据：`active` 启用状态，`from`/`to` 为有效期，`zones` 为可进入的室内区域。
  多张凭据可绑定同一 `person`，人员位置只有一份。
- 读卡器：连接明确的 `from`（起点）与 `to`（终点）区域。
- 事件：`kind` 为 `swipe`（刷卡）或 `correction`（人工纠正，必须带 `reason`）。

## 边界语义

- **时间**：全部为 UTC；凭据有效期为半开区间 `[from, to)`，`from` 当天有效、
  `to` 时刻起失效。事件按时间排序，同一时刻保持输入顺序（稳定排序）。
- **刷卡判定顺序**：凭据存在 → 读卡器存在 → 凭据启用 → 有效期内 →
  目标区域权限（仅进入室内时检查，退出到室外不检查目标权限）→
  人员当前位于读卡器起点 → 目标区域未满。任一失败即拒绝并给出理由。
- **原子性**：拒绝不改变任何位置或人数；成功通行同时更新两侧计数。
  重复进入（人不在起点）与从错误区域离开都会被拒绝。
- **人工纠正**：必须带理由，记录前后位置，仍需满足目标容量；
  纠正成功后，后续事件以已确认的位置继续判断。
- **换卡/停用卡**：不会自动移走人员；人员位置只由成功通行或纠正改变。
- **校验**：缺失引用（未知区域/人员/凭据/读卡器）、重复 ID、
  空有效期等非法配置在回放开始前拒绝，不产生任何部分结果。
- **一致性**：任一时刻的区域名单计数与回放过程的占用计数严格一致。

```sh
go test ./...
```
