# 集合竞价撮合演练工具（Go 标准库）

本地集合竞价（call auction）演练工具：先积累限价买卖单，再通过一次竞价统一
确定成交价并分配数量。**仅用于本题模拟，不连接任何交易所或资金账户。**

仅依赖 Go 标准库（JSONL、`sort`、`bufio`），无第三方依赖。

## 构建与运行

```bash
go build ./...
go test ./...
echo '{"type":"place","id":"b1","side":"buy","price":100,"qty":10}
{"type":"place","id":"s1","side":"sell","price":100,"qty":4}
{"type":"execute","batch":"B1","ref":100}' | go run ./cmd/callauction
```

程序从标准输入逐行读取 JSONL 请求，向标准输出逐行输出 JSONL 响应；
空行忽略，非法 JSON 或非法请求输出一行 `type:"error"`，且**不改变订单簿**。

## 请求格式

所有价格为正整数（单位：分），数量为正整数，订单标识在整个会话中唯一。

| type      | 字段                                   | 说明                                         |
| --------- | -------------------------------------- | -------------------------------------------- |
| `place`   | `id, side("buy"/"sell"), price, qty`   | 下单，成功后返回递增受理序号 `seq`           |
| `cancel`  | `id`                                   | 撤销仍有余量的有效订单；标识之后不可复用     |
| `preview` | `ref`（正整数参考价）                  | 只计算竞价结果，不扣减任何数量               |
| `execute` | `batch`（唯一批次号）, `ref`           | 执行并扣减；同批次同参数重试返回原结果       |

### 幂等规则

- `execute` 的 `batch` 在会话内唯一。
- 相同 `batch` + 相同 `ref` 重试：返回首次的原结果，**不会再次成交**。
- 相同 `batch` 但参数不同：拒绝（`error`），订单簿不变。

## 定价规则

1. 候选价格**只取当前有效订单出现过的价格**。
2. 在候选价 `p` 上累计愿意成交的数量：买单报价 `>= p` 的余量之和为买量，
   卖单报价 `<= p` 的余量之和为卖量。
3. `可成交量 = min(买量, 卖量)`，`失衡量 = |买量 - 卖量|`。
4. 依次比较：最大化可成交量 → 最小化失衡量 → 距离 `ref` 最近 → 仍同分取较低价。
5. 最大可成交量为 0 时没有成交价：返回 `matched:false`、`price:0`，不强行匹配。

## 撮合与分配

在选定的唯一价格上：

- 买单按报价**降序**、卖单按报价**升序**排列；同价按受理序号先后（FIFO）。
- 逐对撮合，每笔成交数量取双方当前剩余的较小值，不超过任一订单余量。
- 所有成交都以同一个竞价价格成交。
- 执行后未成交余量继续保留在订单簿中；全部成交或已撤单的订单不再是有效订单。

响应中：

- `fills`：逐对成交明细（买卖订单 ID、序号、价格、数量）。
- `remaining`：全部订单的委托量、已成交量与余量快照。
- `candidates`：各候选价的买量、卖量、可成交量、失衡量，便于核对定价过程。

执行前会做守恒核对：每笔成交量为正、逐单累计不超过其撮合前余量、
买卖双方成交总量相等；核对失败则不应用结果。

## 典型场景

```jsonl
{"type":"place","id":"b1","side":"buy","price":100,"qty":3}
{"type":"place","id":"b2","side":"buy","price":110,"qty":3}
{"type":"place","id":"s1","side":"sell","price":100,"qty":5}
{"type":"preview","ref":100}
{"type":"execute","batch":"B1","ref":100}
```

- **定价平局**：两个候选价可成交量、失衡量相同且距 `ref` 等距时取较低价，
  见 `TestChoosePriceTieBreaks`。
- **部分成交**：卖方 5、买方按 110 先成交 3 再由 100 成交 2，买单 `b1` 留 1 的
  余量，见 `TestExecutePartialFillAndAllocation`。
- **重复执行**：同批次重试返回同一结果且不再扣减；改参数被拒绝，
  见 `TestExecuteIdempotentAndBatchConflict`。

## 代码结构

- `internal/auction/book.go`：订单簿、下单/撤单校验、受理序号与标识不可复用。
- `internal/auction/pricing.go`：候选价统计与四优先级定价选择。
- `internal/auction/match.go`：排序、逐对撮合（副本计算）、应用成交、守恒核对。
- `internal/auction/engine.go`：预览/执行、批次幂等。
- `cmd/callauction/main.go`：JSONL 标准输入/输出命令行入口。
