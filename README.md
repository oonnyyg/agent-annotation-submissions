# label128 — Code 128 标签核验工具

仅用 Go 标准库实现的 Code 128 编码/解码核验工具，面向标签生产审计。
不生成图片，不依赖任何外部条码库。

## 运行

```sh
go run ./cmd/label128
```

从标准输入按行读取 JSONL 请求，每行独立处理并输出一行 JSON 响应；
某一行的失败（非法 JSON、编码或解码错误）不会阻断后续请求。

## 请求与响应

编码：

```json
{"op":"encode","text":"HI345678"}
{"ok":true,"codes":[104,40,41,99,34,56,78,68,106],"widths":[2,1,1,2,...],"position":-1}
```

解码：

```json
{"op":"decode","widths":[2,1,1,2,1,4,...]}
{"ok":true,"codes":[104,40,41,99,34,56,78,68,106],"text":"HI345678","extra":0,"position":-1}
```

失败：

```json
{"ok":false,"error":"module 36: stop symbol mismatch: got width 1, want 2","position":36}
```

## 支持范围

- 文本仅支持非空可打印 ASCII（空格 `0x20` 到波浪号 `0x7E`）。
- 只使用码集 B 与码集 C；支持起始码集选择与中途切换（CodeB=100、
  CodeC=99）。不支持码集 A、Shift 与 FNC 功能字符。
- 码集 C 的每个数据码字必须消费恰好两位数字；奇数长度的数字串会
  自动用码集 B 处理落单数字。
- 编码在所有合法方案中选择「起始码 + 数据码 + 切换码」总数最少的；
  数量相同时按完整码字序列的字典序取最小（因此不会见到两位数字就
  立即切换，例如 `"123"` 整体用码集 B 更优）。
- 校验码按标准模 103 计算（起始码权重 0，其后码字权重为位置序号），
  之后追加终止符（106）。
- `codes` 为完整码字序列：起始码、数据/切换码、校验码、终止符。
- `widths` 为交替条空的整数模块宽度（从条开始），包含终止符最后的
  条，不包含两侧静区。普通符号 6 个宽度，终止符 7 个（`2331112`）。

## 解码与错误定位

解码从宽度序列恢复码字并依次验证：

1. 长度结构：总宽度数必须是 `6k + 7`（k 个普通符号 + 终止符）。
2. 终止符：末尾 7 个宽度必须等于 `2 3 3 1 1 1 2`。
3. 每个 6 宽度符号必须匹配某个 Code 128 码字模式。
4. 起始码必须是 B（104）或 C（105）。
5. 校验码必须等于对前面码字重算的模 103 值；校验码即使数值上等于
   切换码（99/100）也只作为校验，不参与文本解释。
6. 按码集状态机恢复文本；码字在码集 B 中须为 0–94 或 CodeC，在码集
   C 中须为 0–99 或 CodeB。

错误响应中的 `position` 指出问题位置：编码时为文本中的字节偏移，
解码时为宽度序列中的条目索引（符号起始处），无法定位时为 `-1`。

合法但不是最短的编码（例如本可用码集 C 却全程用码集 B）仍可正常
解码；响应中的 `extra` 字段报告该序列的「起始 + 数据/切换」码字数
比同一文本的规范最短编码多几个。

## 测试

```sh
go test ./...
```

覆盖：已知校验向量（`HI345678` → 校验码 68）、奇数数字串、码集切换、
平手时的字典序选择、校验码等于切换码值、损坏终止符、校验错误、
非最短编码的 `extra` 报告及编解码往返。
