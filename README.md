# marccheck — 书目核验工具

从连续的 MARC21 二进制记录中提取书目信息，输出书目 CSV 与结构及关联诊断 JSON，
并找出同一书号对应不同题名的可疑记录。仅使用 Go 标准库，不访问任何在线书目。

## 用法

    go run ./cmd/marccheck [-csv out.csv] [-json out.json] <input.mrc>

- -csv：书目 CSV 输出路径，默认 catalog.csv，- 表示标准输出。
- -json：诊断 JSON 输出路径，默认 diagnostics.json，- 表示标准输出。

CSV 列：index, control_number, title, valid_isbns, invalid_isbns
（同一记录的多个有效书号以空格分隔）。

JSON 包含：
- structural：结构诊断（offset 为字节偏移，fatal 表示是否终止解析）；
- groups：按共享有效规范书号建立的记录连通组，conflict: true 表示组内
  存在不同题名；
- summary：解析/坏记录/组/冲突组计数及是否提前停止。

## 格式范围

- 仅支持 UTF-8 编码的 MARC21（ISO 2709 结构）记录；字段内容含无效 UTF-8
  的记录被拒绝并隔离。不支持 MARC-8 等其他编码，不做任何在线查询。
- 记录头标 24 字节：0-4 为记录长度，12-16 为数据基地址。所有长度与偏移
  一律按字节计算，不按中文字符数计算。
- 目录项为 12 字节（tag 3 + 长度 4 + 偏移 5），目录以字段终止符 0x1E
  结束；每个字段以 0x1E 结束，记录以 0x1D 结束。越界的字段范围、
  缺失的终止符、非数字目录项均判为坏记录。
- 字段的物理排列与目录顺序可以不同：读取完全按目录项中的字节偏移定位。
- 重复字段与重复子字段按出现顺序保留；控制字段（tag < 010）不按子字段
  切分，保留原始值。
## 数据提取规则

- 控制号取第一个 001 字段值。
- 题名按目录顺序拼接所有 245 字段的 a、b 子字段，以单个空格连接。
- 书号取所有 020 的 a 子字段。

## 书号规范化

- 只去掉空格与连字符，然后验证 ISBN-10 或 ISBN-13 校验位（ISBN-10 末位允许 X）。
- 有效 ISBN-10 转换为以 978 开头的 ISBN-13；已有 ISBN-13 必须以 978 或 979 开头，否则视为无效。
- 无效书号列入 CSV 的 invalid_isbns，且不参与任何关联。

## 关联与题名比较规则

- 以共享的有效规范书号（ISBN-13）建立记录连通组（并查集），一条记录可有多个书号，关联可传递。
- 组内题名只在压缩空白后比较（去除首尾空白、连续空白压缩为单个空格）；不同的题名原样保留在 titles 中并将组标记为 conflict: true，不自动合并或改写题名。

## 坏记录处理

- 当头标长度是不少于 26 且未超剩余字节的整数时，坏记录按此边界隔离，解析从该边界之后继续，诊断记为非致命。
- 否则（长度非整数、小于 26 或超出剩余字节）解析停止，记录致命诊断及其字节偏移。
