# blocking-workshop-replay

本地车间回放工具：读取工位与工单路线的 JSON 描述，按离散事件仿真
重演整个加工过程，输出每道工序的时间 CSV 与状态摘要 JSON，解释工单
为何等待（排队）或占机阻塞（blocking），并区分「真正完成」与
「没有事件可推进的停滞（stall）」。本工具只做确定性回放，不求最优排程。

## 运行

```sh
go run ./cmd/workshop -stations examples/stations.json -jobs examples/jobs.json \
    -csv ops.csv -summary summary.json
```

四个参数均有默认值（`stations.json`、`jobs.json`、`ops.csv`、`summary.json`）。

## 输入模型

- `stations.json`：`[{"id": "A", "buffer": 0}, ...]`
  - 每工位一台机器；`buffer` 为等待缓冲容量，非负整数，**不含加工件**。
- `jobs.json`：`[{"id": "J1", "release": 0, "route": [{"station": "A", "duration": 2}]}, ...]`
  - `release` 为非负整数释放时刻；`route` 为有限工序序列，可重复访问同一工位；
    `duration` 为正整数。
- 校验拒绝：未知工位、重复的工位/工单编号、空路线、负释放、非正时长、负缓冲。
  所有编号比较一律按字典序。

## 事件顺序

仿真按离散事件推进，不逐时间单位轮询。事件为「工单释放」与「加工完成」：

1. 时间前进到下一事件时刻，**先登记该时刻的全部释放与全部完成**：
   - 释放的工单进入「外部等待」，等待首站接收；
   - 末工序完成的工件立即离开系统并释放机器；
   - 非末工序完成的工件留在原机上，进入占机阻塞状态。
2. 然后**反复执行转移与开工，直到无变化**：
   - 每轮先按**工单编号字典序**处理所有可行转移（外部等待 → 首站，
     阻塞件 → 下站），再按**工位编号字典序**让空闲机器从缓冲队首开工；
   - 接收规则：缓冲有空位则入队；零容量只能在机器空闲时**直接交接**上机；
   - 转移失败不丢件，工件继续占机等待下一轮；由于必须先能被下站接收
     才释放原机，零容量满机的循环互换（绕过容量的死锁交换）不会发生。

## 停滞与完成

- 所有工单完成：`status = "completed"`。
- 仍有未完成工单，但没有任何未来事件（无在加工件、无未来释放）且
  当前轮无任何可行转移：`status = "stalled"`，摘要中的 `stall` 字段
  报告停滞时刻与占用关系——每台被阻塞机器持有的工单及其目的站
  （含缓冲中排队的工单），以及仍在外部等待首站的工单。

## 统计边界

- **排队（queue）**：从工单释放（首站）或上站转出时刻起，到本工序
  在机器上开工为止。外部等待首站的时间计入排队。
- **加工（processing）**：各工序时长之和，即开工到完成的区间。
- **占机阻塞（blocked）**：工序完成到工件实际离开机器的区间；
  末工序完成立即离开，阻塞恒为 0。

CSV 每行对应一道工序：`enqueue,start,end,leave` 为上述边界时刻，
`queue = start - enqueue`，`blocked = leave - end`。
