# label128 — Code 128 标签核验工具

仅用 Go 标准库实现的 Code 128 编码/解码核验工具，面向标签生产审计。
不生成图片，不依赖外部条码库。

## 运行

```
go run ./cmd/label128
```

从标准输入按行读取 JSONL 请求，每行独立处理并立即输出一行 JSON 响应；
某一行失败（JSON 非法、文本非法、条码损坏）不会阻断后续请求。

## 请求与响应

编码：

```
{"op":"encode","text":"ABC1234"}
{"ok":true,"codewords":[104,33,34,35,17,18,19,20,1,106],"widths":[2,1,1,2,1,4,...]}
```

解码：

```
{"op":"decode","widths":[2,1,1,2,1,4,...]}
{"ok":true,"text":"ABC1234","codewords":[104,33,34,35,17,18,19,20,1,106],"extra_codewords":0}
```

失败响应：

```
{"ok":false,"error":"...","kind":"module","offset":42}
```

## 支持范围

- 文本：非空可打印 ASCII（空格 0x20 到波浪号 0x7E）。
- 码集：仅 B 与 C。支持起始集选择与中途 Code B / Code C 切换；
  C 码集中每个数据码字必须消费恰好两位数字（奇数位数字会切回 B）。
- 不支持 A 码集、FNC1–FNC4、Shift 等功能字符；解码遇到即报错。
- 校验：标准模 103 校验码；终止符固定为 `2331112`（7 个模块，含最后的条）。
- 宽度序列：交替条/空的整数模块宽度（1–4），不含两侧静区。

## 最优编码规则

在所有合法编码中选取「起始码 + 数据码字 + 切换码字」总数最少的方案；
总数相同按完整码字序列（含起始码值）字典序取最小。采用动态规划全局
求优，不会因见到两位数字就立即切换（例如 `A12` 保持 B 码集，
`ABC1234` 也保持 B 码集，因为切换的代价不小于收益）。

## 解码与错误定位

解码依次执行：模块宽度合法性（1–4）→ 长度 6n+7 → 终止符 `2331112`
→ 每 6 模块映射码字 → 起始码字（104/105）→ 模 103 校验 → 按码集状态
恢复文本。校验码字即使等于 99/100（Code C/B 切换值）也只作校验，
不参与文本解释。

错误通过 `kind` 与 `offset` 定位：

- `module`：宽度序列问题（越界宽度、长度不符、终止符损坏、无法映射的
  6 模块组），`offset` 为出问题的模块下标。
- `codeword`：起始码字非法（如 Start A），`offset` 为码字下标。
- `checksum`：模 103 校验不匹配，`offset` 为校验码字下标。
- `logic`：码字序列逻辑错误（如 C 码集中出现非数字码字、冗余切换），
  `offset` 为码字下标。

合法但非最短的编码仍可正常解码，响应中的 `extra_codewords` 报告它比
规范最短编码多用了几个数据/切换码字。
