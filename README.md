# git-pack-object-reader

一个**离线** Git Pack 检查工具：从指定的 `.pack` 归档中恢复全部对象并生成核对清单。
全程只使用 Go 标准库，**不调用 git 命令，也不读取或修改任何真实仓库**。

## 用法

```sh
go run ./cmd/packcheck -pack path/to/file.pack -out output-dir \
    [-max-object-size N] [-max-delta-depth N]
```

- `-pack`：待检查的 pack 文件路径（必填）。
- `-out`：输出目录（必填，**必须不存在**，工具绝不覆盖已有目录）。
- `-max-object-size`：单个恢复对象的最大字节数，默认 1 GiB，超限明确失败。
- `-max-delta-depth`：差分链最大深度，默认 64，超限明确失败。

输出目录中包含：

- 以对象 ID（SHA-1 十六进制）命名的**原始字节**文件，每个对应一个恢复出的对象正文；
- `MANIFEST.txt`：核对清单，列出每个条目的包内偏移、最终类型、恢复后大小、
  差分深度、对象 ID 以及差分来源（`ofs:<偏移>` 或 `ref:<对象ID>`）。

所有校验与对象写盘都在临时目录中完成，**全部成功后才原子地发布输出目录**；
任何失败只打印诊断，不留下半份正式导出。

## 格式范围

- 仅支持 SHA-1 仓库的 **pack 第 2 版**（`PACK` 魔数 + version 2）。
- 支持四种普通对象类型：commit、tree、blob、tag。
- 支持两种差分条目：
  - `OBJ_OFS_DELTA`（按包内偏移引用基对象）；
  - `OBJ_REF_DELTA`（按对象 ID 引用基对象，基对象可能出现在包内**后面**的位置）。
- 基对象本身可以继续是差分（链式差分），最终对象类型继承自链根的普通对象。
- 对象 ID 按 Git 规则计算：`sha1("<type> <size>\0" + body)`。

## 校验与拒绝行为

以下情况会被明确拒绝并给出诊断（包含关联条目的偏移）：

- 包尾 SHA-1 摘要与内容不符；
- 声明条目数量与实际不符、未知类型码、截断数据、条目之后的多余字节；
- 条目声明的解压长度与实际 zlib 解压长度不一致；
- 差分基对象缺失或无法解析（**只接受自包含归档**，不会求助外部仓库）；
- 差分头声明的基对象大小与实际基对象不符；
- 越界复制、截断或非法（0x00）差分指令——失败时不产生任何部分对象；
- 恢复结果大小与差分声明的结果大小不符；
- 超过配置的对象大小或差分深度上限；
- 输出目录已存在。

注意区分两种“大小”：条目头声明的是**该条目差分数据（或正文）解压后的长度**，
而清单中的 SIZE 是**重建完成后对象正文的长度**，二者对差分条目通常不同。

## 限制

- 不支持 pack 第 3/4 版、SHA-256 仓库、多包索引（`.idx`）与增量薄包（thin pack）：
  归档必须自包含。
- 整个 pack 与对象在内存中处理，超大归档受内存限制。

## 测试

```sh
go test ./...
```

测试覆盖：四种普通对象、ofs/ref 差分、基对象在后的 ref 差分、链式差分、
损坏归档（摘要错误、截断、多余尾部、未知类型、声明数量/大小不符）、
缺失基对象诊断、非法差分指令、大小与深度上限、导出的原子性与不覆盖语义。
