# ruleaudit — 决策表上线前静态分析器

读取 JSON 描述的字段域与有序规则，精确找出**未覆盖区域**、**重叠/冲突区域**和**被遮蔽规则**，并为每个问题给出可直接复现的最小输入。仅使用 Go 标准库，不执行任何外部表达式。

## 运行

```sh
go run ./cmd/ruleaudit examples/discount.json   # 从文件读取
go run ./cmd/ruleaudit < spec.json              # 从标准输入读取
go test ./...                                   # 运行测试
```

## 规则格式

```json
{
  "strategy": "first | unique",
  "cell_limit": 1000000,
  "fields": [
    { "name": "tier", "type": "enum", "values": ["free", "pro"] },
    { "name": "age",  "type": "int",  "min": 0, "max": 120 }
  ],
  "rules": [
    {
      "id": "child-free",
      "output": "0.5",
      "when": {
        "tier": { "enum": ["free"] },
        "age":  { "range": { "min": 0, "max": 12, "max_exclusive": false } }
      }
    }
  ],
  "samples": [ { "tier": "free", "age": 10 } ]
}
```

- **字段**：只支持有限枚举（`enum` + `values`，声明顺序即取值顺序）和有界整数（`int` + `min`/`max`，闭区间）。
- **规则**：`when` 中各字段条件的合取；省略字段表示不限。枚举条件为值集合，整数条件为带 `min_exclusive` / `max_exclusive` 开闭端点的区间。
- **校验**：未知字段、未知枚举值、完全落在域外的区间、规范化后为空的条件区间都会被拒绝，报错定位到规则 `id`。
- **策略**：
  - `unique`：任何输入命中多条规则即冲突（即使输出相同也不通过）。
  - `first`：返回最早命中的规则，同时保留全部匹配记录；被前面多条规则**联合**完全遮蔽的规则会被识别并列出遮蔽者。
- **samples**：可选，逐条求值并与静态分析口径一致（唯一命中下多条命中报冲突，首条命中下给出首条与全部匹配）。

## 分析方法与见证顺序

- 按所有规则边界把每个字段切成原子区间（枚举每值一个，整数按端点切分），笛卡尔积得到**等价单元**；同一单元内匹配结果完全一致，因此结论是精确的，不依赖随机采样。
- 单元总数超过 `cell_limit`（默认 1,000,000）时明确报告“分析未完成”，不给出任何无冲突/全覆盖结论。
- 反例与见证取**最小输入**：按字段声明顺序比较，枚举按声明顺序、整数按数值顺序。
- 报告中的区域给出每个字段的边界（如 `age∈[13,17]`）及该区域的复现输入。

## 规模限制

等价单元数 = 各字段原子区间数的乘积。规则边界越多单元越多；整数域很大但规则边界少时单元数仍然很小。超限时请提高 `cell_limit` 或缩小字段域。
