# incremental-build-runner

仅用 Go 标准库实现的小型本地构建器：按依赖顺序执行命令，内容未变化时复用缓存结果。无后台服务，单次进程内完成校验、执行与报告。

## 清单格式

`build.json`（清单所在目录即工作根，命令的工作目录固定为工作根）：

```json
{
  "targets": {
    "gen":   {"command": ["tool", "in.txt", "mid.txt"], "inputs": ["in.txt"], "outputs": ["mid.txt"]},
    "final": {"command": ["tool", "mid.txt", "out.txt"], "deps": ["gen"], "inputs": ["mid.txt"], "outputs": ["out.txt"]}
  }
}
```

- `command`：参数数组，直接 `exec` 启动，不经过 shell，不隐式拼接。
- `deps`：依赖目标名；`inputs`/`outputs`：显式声明的相对路径文件。

## 使用

```
go run . -manifest build.json [-cache-dir DIR] [-dry-run] [目标...]
```

- 不带目标时构建全部；带目标时只执行其依赖闭包。
- `-dry-run` 只输出执行计划，不运行命令、不写缓存。
- 标准输出为 JSON 报告；逐目标日志在 `<cache-dir>/logs/<目标>.log`。
- 存在失败目标时进程以非零码退出。

## 运行边界与规则

- **路径安全**：所有输入/输出必须是工作根内的相对路径；拒绝绝对路径、`..` 越界与符号链接组件。
- **输出归属**：一个输出文件只能属于一个目标；把其他目标的输出当输入必须声明对应 `deps`。
- **先校验后执行**：加载时校验完整依赖图，未知目标、重复依赖、自依赖、环都会直接拒绝，不会先执行部分命令。
- **顺序**：拓扑排序；无依赖关系的目标按名称字典序，顺序确定。
- **缓存指纹**：SHA-256 覆盖命令参数、输入文件内容、直接依赖的输出文件内容（不含修改时间）。命中还要求本目标全部输出存在且内容与缓存记录一致（防外部篡改）。文件改回原来的内容即恢复命中，不因 mtime 变化重建。
- **失败语义**：命令非零退出或缺少声明输出即失败，不写缓存；依赖失败的目标标记 `skipped`，无关分支继续执行。
- **干跑语义**：上游计划重建时，下游标记 `pending-upstream`（新输出指纹待上游结果决定），不会假装已知。
- **缓存持久化**：`<cache-dir>/cache.json`（默认 `<工作根>/.buildcache`），重启后可复用。

## 报告状态

| 状态 | 含义 |
| --- | --- |
| `cached` | 缓存命中，未执行 |
| `rebuilt` | 实际执行并成功（reason 说明重建原因） |
| `failed` | 命令失败或缺少声明输出 |
| `skipped` | 依赖失败而跳过 |
| `would-run` / `would-cache` | 干跑：将重建 / 将命中 |
| `pending-upstream` | 干跑：上游将重建，结果待定 |

## 测试

```
go test ./...
```

覆盖：内容失效与恢复、输出篡改、分支失败与跳过、缺少声明输出、干跑不改缓存、清单校验（越界/符号链接/环/输出冲突/未声明依赖）、拓扑顺序确定性。
