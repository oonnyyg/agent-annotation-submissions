# marccheck — 书目核验工具

从连续 MARC21 二进制记录中提取书目信息，输出书目 CSV 与结构/关联诊断 JSON，
并找出同一书号对应不同题名的可疑记录。仅使用 Go 标准库，仅支持 UTF-8 记录，
不访问任何在线书目服务。

## 用法

```
go run ./cmd/marccheck [-csv out.csv] [-json out.json] input.mrc
```

- `-csv`：书目 CSV 输出路径（默认 `catalog.csv`）
- `-json`：诊断 JSON 输出路径（默认 `diagnostics.json`）

## 格式范围

- 输入为连续拼接的 MARC21 二进制记录（ISO 2709 结构），编码必须为 UTF-8；
  含无效 UTF-8 的记录被拒绝并按坏记录处理。
- 按记录头（24 字节）中的记录长度与数据基地址解析目录；所有长度与偏移
  一律按**字节**计算，不按中文字符数计算。
- 校验目录项（tag 为 3 位数字、长度/偏移为数字）、字段范围（不超出字段区）
  及终止符（目录与字段 `0x1E`，记录 `0x1D`）。
- 字段的物理排列顺序与目录顺序不同时，仍按目录中的偏移正确定位读取。
- 重复字段与重复子字段按原始顺序保留；控制字段（001–009）不按子字段切分。

## 提取规则

- 控制号：第一个 `001` 控制字段。
- 题名：按目录顺序拼接所有 `245` 字段的 `a`、`b` 子字段，以空格连接。
- 书号：取 `020` 的 `a` 子字段。

## ISBN 规则

- 仅去掉空格与连字符，然后验证 ISBN-10 或 ISBN-13 校验位；
  ISBN-10 末位允许 `X`。
- 有效 ISBN-10 转换为以 `978` 开头的 ISBN-13；已有 ISBN-13 必须以
  `978` 或 `979` 开头。
- 校验失败的书号记入 `invalid_isbns`，**不能**建立记录关联。

## 关联与题名比较规则

- 以共享的有效规范书号（ISBN-13）对记录做连通分组；一条记录可有多个书号，
  关联可传递（A–B 共享一号、B–C 共享另一号，则 A、B、C 同组）。
- 组内题名只在**压缩空白后**比较（连续空白折叠为一个空格）；不做任何其他
  规范化，也不自动合并。题名不一致的组标记为冲突（`conflict: true`）。

## 坏记录隔离

- 当记录头长度为不少于 26 且不超过剩余字节数的整数时，坏记录按此边界
  隔离，跳过该长度后继续解析后续记录，并记入诊断 JSON 的 `bad_records`
  （含字节偏移与跳过长度）。
- 否则解析停止，诊断 JSON 记录 `stopped_at`（字节偏移）与 `stop_reason`。

## 输出

CSV 列：`index, control_number, title, isbns, invalid_isbns, group_id, conflict`。

诊断 JSON：`records_parsed`、`bad_records`（offset/length/error）、
`stopped_at`/`stop_reason`（如发生）、`groups`（id/members/isbns/conflict）。
