# 轨道进路离线回放器

一个纯离线的 Go 命令行工具，用简化场景检查**进路申请**与**列车推进**事件序列是否相容。
它不连接、不控制任何真实铁路设备，仅用于配置与事件序列的离线验证。

## 构建与运行

```sh
go build .
./railway-route-replay -config examples/config.json -events examples/events.jsonl
# 事件也可从标准输入读取（省略 -events）
```

配置非法时程序在回放前直接拒绝并退出（退出码 1）。

## 配置格式（JSON）

```json
{
  "sections": ["A", "B", "C"],
  "switches": {"W1": "normal"},
  "routes": [
    {"id": "R1", "sections": ["A", "B", "C"], "switches": {"W1": "normal"}}
  ]
}
```

- `sections`：全部区段编号，初始均为空闲。
- `switches`：全部道岔及其明确的初始位置（`normal` / `reverse`）。
- `routes`：每条进路的有序区段序列及要求的道岔位置。

校验规则：区段/道岔/进路编号不得重复；一条进路内区段不得重复；
所有引用必须存在；道岔位置必须合法。违反任一规则即拒绝回放。

## 事件格式（JSONL，每行一条）

| op           | 字段                     | 含义                             |
|--------------|--------------------------|----------------------------------|
| `request`    | `route`                  | 申请并锁闭进路                   |
| `cancel`     | `route`                  | 取消进路（仅列车未进入时允许）   |
| `enter`      | `train`, `route`         | 列车进入该进路首区段             |
| `advance`    | `train`                  | 列车推进一个区段                 |
| `set_switch` | `switch`, `position`     | 手动转动道岔                     |
| `snapshot`   | —                        | 输出区段占用与道岔持有者快照     |

每条事件输出一行决策 JSON：`{"line":N,"op":...,"decision":"accepted|rejected","reason":"..."}`，
`snapshot` 事件额外携带 `snapshot` 字段。

## 联锁规则

- 申请进路时一次性检查全部区段与道岔：任一区段已被其他进路锁闭，
  或任一道岔被持有在与要求不同的位置，即整体拒绝，不遗留部分锁或已改变的位置。
- 同一道岔被多条进路要求**相同**位置时允许共享持有；释放一条进路只清除自己的持有。
- 道岔只要仍被任一进路持有，就不能被手动转到另一位置。
- 列车按事件进入首区段并逐段推进（单区段占用模型）：推进时同时清空前区段。
  未申请进路、列车不在进路上、同一列车同时进入两条进路均被拒绝且不改状态。
- 区段锁保留到列车从末区段退出后随进路整体释放。
- 取消只允许在列车尚未进入时执行，行车中禁止通过取消解除保护。

## 模型简化范围

本工具是教学/验证用的简化模型，**不**覆盖真实联锁的以下方面：

- 无信号机、轨道电路、计轴等真实设备建模，无接近锁闭与时间延迟。
- 单区段占用：列车任意时刻只占一个区段，无车长、无跨区段占用。
- 无进路重叠（overlap）、侧防、保护区段与敌对进路的完整图搜索；
  冲突仅按共享区段与道岔位置判定。
- 道岔转换瞬时完成，无转换过程与锁闭继电器时序。
- 单线程顺序回放，无并发与故障注入。
