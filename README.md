# 项目工期压缩分析器（CPM Crash Planner）

纯 Go 标准库实现的关键路径法（CPM）分析与工期压缩（crashing）决策工具。
只做数学分析，不执行任何真实任务，也不与项目管理平台对接。

## 输入格式（JSON）

```json
{
  "budget": 12,
  "activities": [
    {"id": "start", "duration": 0, "predecessors": []},
    {"id": "design", "duration": 4, "predecessors": ["start"],
     "crash": {"shorter_duration": 2, "cost": 6}},
    {"id": "build", "duration": 6, "predecessors": ["design"]},
    {"id": "done", "duration": 0, "predecessors": ["build"]}
  ]
}
```

校验规则：

- 活动集合非空，`id` 唯一且非空；工期为非负整数，允许零工期里程碑。
- 依赖必须引用已知活动、不可重复、不可自依赖；依赖图存在环时报错。
- 所有无前置活动从第 0 天开始；时间单位为“天”，采用完成到开始（FS，时距 0）关系。
- 每项活动至多一个可选压缩方案：压缩后工期必须**严格短于**原工期且非负，成本为正整数。
 可压缩活动至多 **18** 项；同一项只能选或不选，不能多次压缩。
- 预算为非负整数。

## 计算方法

1. **拓扑排序**：Kahn 算法检测环，同层按标识排序以保证结果确定。
2. **前推**：`ES = max(前置 EF)`，`EF = ES + 工期`；项目完工日 = 全部活动 `EF` 的最大值。
   多个独立分支共用同一项目终点，不分别假设终点。
3. **后推**：无后继活动的 `LF = 项目完工日`，`LS = LF - 工期`；
   有后继者 `LF = min(后继 LS)`。总时差 `TF = LS - ES`。
4. **关键路径**：在“零总时差且边界时间相接（前置 EF = 本活动 ES）”的子图上，
   以动态规划求一条从第 0 天源点到完工日汇点的完整路径；
   多条路径时选择活动标识序列**字典序最小**者，而不是把所有零时差活动简单拼接。
5. **压缩选择**：对可压缩活动的全部 2^k 个子集做全局枚举（k ≤ 18，最多 262 144 种），
   逐组合重新计算全部时差与关键路径。超预算组合直接排除。
   比较规则依次为：整体完工日最早 → 总成本最低 → 排序后的已选活动标识序列字典序最小。
   不使用按单项收益的贪心（压非关键活动不会提前完工）。

压缩后关键路径可能转移；输出始终保留基准与最优方案两套结果对照。

## 输出

- 终端摘要：基准/最优完工日、已选活动、成本与两套关键路径。
- `-csv`：基准与压缩后逐项时间参数对照（ES/EF/LS/LF/总时差/关键标记），含 UTF-8 BOM。
- `-json`：选择理由报告（枚举组合数、预算内可行组合数、平局规则、逐项对照）；
  未指定文件时打印到标准输出。

## 使用

```sh
go run . -input examples/project.json -csv plan.csv -json decision.json
```

## 计算规模

- 常规 CPM（拓扑 + 前推 + 后推 + 关键路径 DP）为 O(V + E)。
- 压缩搜索为 O(2^k · (V + E))，k ≤ 18；单次组合仅一次完整 CPM 重算，
  在普通机器上毫秒级完成（测试中 2^18 组合约 2 秒级，含 Go 测试启动开销）。

## 明确不包含的约束

- 不考虑人员、机械、材料等资源限制与资源平衡/资源平滑。
- 不考虑工作日历、节假日、周末与每日工时，所有时间为连续自然“天”。
- 仅支持完成-开始（FS、时距 0）依赖，不含 SS/SF/FF 或提前量/滞后量。
- 每项活动只有“正常/压缩后”两档工期，不支持线性连续赶工或多档方案。
- 不模拟不确定性（三点估算、概率网络）、成本时间以外的风险因素。
- 不执行真实任务、不读写外部项目平台（Jira、MS Project 等）。
