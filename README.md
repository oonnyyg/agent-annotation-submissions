# fragcap — 离线 IPv4 分片 UDP 抓包分析器

`fragcap` 读取经典 PCAP 文件，重组 IPv4 分片中的 UDP 数据报，
把确认完整的数据报与无法确认完整的内容分开报告。纯 Go 标准库实现。

## 用法

```
go run ./cmd/fragcap [-datagrams out.jsonl] [-summary summary.json] <input.pcap>
```

- 数据报 JSONL 默认写 stdout，`-datagrams` 指定文件。
- 异常摘要 JSON 默认写 stderr，`-summary` 指定文件。

## 输入支持范围

- 仅经典 PCAP（libpcap）格式，**不支持 PCAPNG**；不抓取实时网络。
- 自动识别大端 / 小端，以及微秒 / 纳秒时间戳变体（magic 判定）。
- 仅支持以太网承载（LINKTYPE_ETHERNET=1）的 IPv4 UDP。
  不支持 Linux cooked capture、raw IP、802.1Q VLAN 嵌套、IPv6、
  GRE/VXLAN 等隧道封装——这些链路类型或协议会被拒绝或计数跳过。

## 校验与解析

- 校验每条记录的捕获长度（含 sanity 上限），捕获长度小于线上长度
  （抓取截断）时计入 `truncated_records` 并报告记录号。
- 解析以太网与 IPv4 头长（IHL）和总长，验证 IP 头校验和；
  非法目标包在摘要中定位到具体记录号。
- 非 IPv4 帧、非 UDP 的 IPv4 包分别计数后跳过。

## 分片重组规则

- 按（源地址、目的地址、协议、标识号）聚合，支持乱序到达。
- 片偏移以 8 字节为单位；非末片（MF=1）负载长度必须是 8 的倍数。
- 末片（MF=0）确定总长后，任何越界内容或与之矛盾的末片长度都判为冲突。
- 完全相同的重叠字节只计一次；重叠内容不同的整组判为冲突，
  不做先到 / 后到覆盖。
- 只有从 0 到末尾无缺口才解码 UDP：UDP 长度必须等于重组负载长度，
  并验证非零校验和（校验和为 0 按 IPv4 惯例跳过验证）。
- 输入保证同一聚合键只代表一个数据报，因此读完整份文件后才定案，
  不提前发布。
- 缺片的组报告缺口范围（`incomplete`）；从未见到末片、总长未知的
  单独标记为 `last_fragment_missing`。不完整数据不计入流量统计。

## 输出

数据报 JSONL 每行一条：

```json
{"record":3,"src":"10.0.0.1","dst":"10.0.0.2","src_port":1234,"dst_port":53,"ip_id":7,"udp_payload_length":22,"udp_payload":"aGVsbG8="}
```

摘要包含记录数、截断记录数、非 IPv4 / 非 UDP 计数、非法包计数、
完整数据报数、异常列表，以及按有向五元组
（源 IP:端口 → 目的 IP:端口）汇总的完整数据报数与 UDP 负载字节数；
重复分片不重复累计。

## 限制

- **标识号复用**：聚合键不含时间维度。若同一（源、目的、协议、ID）
  组合在文件中复用于多个数据报，其分片会混入同组并大概率判为冲突。
  输入需保证同一聚合键只代表一个数据报。
- 不支持的封装：VLAN（802.1Q）、IPv6、隧道（GRE/VXLAN/IPIP）、
  非以太网链路类型。
