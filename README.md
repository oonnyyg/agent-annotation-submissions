# histogram-window-audit

离线分析多实例服务的 Prometheus 风格累计直方图快照，生成指定时间窗口内可解释的延迟统计。
纯 Go 标准库实现，只读取本地 JSONL 文件，不连接任何监控服务。

## 输入格式

每行一个 JSON 快照，输入可乱序：

```json
{"instance":"a","ts":100,"boot":"b1","bounds":[0.5,1],"counts":[1,2,4],"sum":2}
```

- `instance` / `ts`：实例名与整数秒时刻，二者联合唯一（重复拒绝）。
- `boot`：启动代号，用于识别进程重启。
- `bounds`：有限桶上界，至少一个，严格递增且为正；隐含末桶为 `+Inf`。
- `counts`：累计桶计数，长度 `len(bounds)+1`，非负且随桶界不减，末桶即总请求数。
- `sum`：累计总耗时，非负；总数为零时必须为零。

## 用法

```sh
go run . -input snapshots.jsonl -start 100 -end 200 \
  -instances a,b -quantiles 0.5,0.9,0.99 -json report.json -csv buckets.csv
```

- `-instances` 留空表示输入中的全部实例。
- `-json` 留空时报告写到标准输出；`-csv` 留空则不生成。

## 统计口径

- 查询的起止时刻必须在**每个**实例中都有精确快照；缺失端点或窗口内桶界不一致都会报错，
  不做插值补齐，也不悄悄跳过实例。
- 先逐实例计算窗口内所有相邻快照区间，再合并桶差与总耗时，绝不先加实例再判断重启：
  - 相邻快照 `boot` 相同：按差值计量。桶差须非负且累积有序，总耗时差须非负，否则报错。
  - `boot` 改变：只计新快照的累计值，并在报告的 `restart_gaps` 中标记一次统计缺口。
- 输出观测到的请求量、平均耗时（零请求时为 `null`）和每秒请求数（`total / (end-start)`）。
- 分位数 `q ∈ [0,1]`：用累计计数定位桶，在有限桶内按桶宽线性插值，首桶下界取零；
  落入 `+Inf` 桶时返回最后有限上界；零请求返回 `null`；非空分布的零分位取零。

## 统计缺口与假设（重要）

- **重启缺口不还原**：`boot` 变化意味着旧进程末次采样之后、新进程首次采样之前的请求
  无法从快照得知。本工具只把新进程的累计值计入窗口，并在 `restart_gaps` 中如实标记缺口，
  **不宣称完整还原重启期间的流量**。报告中的请求量是下界，缺口期间的实际流量未知。
- **插值假设**：分位数假定请求在桶内均匀分布（线性插值），这只是估计；`+Inf` 桶没有上界，
  落入时分位数退化为最后有限上界，可能低估真实尾部延迟。
- 快照是离线采集的累计计数器，窗口边界之外的采样不影响结果。
