# Expiring Leave Bank

一个本地假期额度台账：按批次管理员工的假期额度，记录每次请假核销了哪批
额度，并保证撤销旧申请不会让已过期的额度重新可用。仅使用 Go 标准库，
所有数量均为整数分钟。

## 运行

```sh
go run ./cmd/leavebank -dir <状态目录>
```

从标准输入读取 JSONL（每行一个操作），每个操作输出一行 JSON 结果；
状态持久化在 `<状态目录>/state.json`，重开程序后批次与申请状态保留。

## 操作

```json
{"op":"grant","batch":"B1","employee":"alice","start":"2026-01-01","end":"2026-04-01","minutes":4800,"date":"2026-01-01"}
{"op":"request","id":"R1","employee":"alice","date":"2026-02-10","minutes":240}
{"op":"cancel","id":"R1","date":"2026-03-01"}
{"op":"balance","employee":"alice","date":"2026-02-11"}
{"op":"usage","employee":"alice"}
```

- `grant`：发放一个额度批次，批次编号全局唯一。
- `request`：申请请假，返回 `approved`（含每批扣减明细）、`rejected`
  （余额不足，整单拒绝）或 `duplicate`（幂等重放）。
- `cancel`：按冻结明细撤销申请，返回退回明细及其中已过期/仍有效的分钟数。
- `balance`：查询某员工在指定日期的余额分类。
- `usage`：列出某员工每次申请的逐批核销明细。

## 自定义额度规则

1. **批次有效期**：左闭右开 `[start, end)`，即生效日当天可用、到期日当天
   起不可用。
2. **操作日期单调**：所有带日期的操作（含查询）只能非递减推进；过期判断
   完全由操作/查询日期决定，从不读取机器当前时间。
3. **当日核销**：请假只核销操作当日有效的额度，不为未来日期预占。
4. **扣减顺序**：先扣最早到期的批次，到期日相同按批次编号字典序；允许
   跨批扣减；余额不足整单拒绝，不留下部分扣款。
5. **幂等申请**：申请编号重复且内容（员工、日期、分钟）完全相同，优先于
   日期校验直接返回原结果，不推进日期、不重复扣减；内容不同报冲突。
6. **冻结分摊**：申请成功即冻结每批扣减明细，之后新增额度不会改变历史
   分摊。
7. **原路退回**：撤销严格按冻结明细退回原批次，且只退一次，不按当前顺序
   重新分配。撤销时批次已到期的部分记为“过期归还”，永久不再计入可用
   余额；仍有效的批次退回后继续参与后续请假。
8. **余额分类与守恒**：`balance` 分别列出 `available`（可用）、`used`
   （已冻结）、`pending`（未生效）、`expiredUnused`（到期未用，含过期
   归还），四类之和恒等于所有批次发放总量 `total`，程序内部每次查询
   都会核对该守恒式。

## 测试

```sh
go test ./...
```

覆盖跨批申请、余额不足整单拒绝、到期后撤销（含过期归还与只退一次）、
重复请求幂等与冲突、日期回退拒绝、持久化重载以及全生命周期守恒。
