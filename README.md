# fragcap — 离线 IPv4 分片抓包审计器

`fragcap` 读取经典 libpcap 抓包文件，把 IPv4 分片重组为 UDP 数据报，
并将**确认完整**的流量与**无法确认完整**的内容分开报告。全程离线，
不抓取实时网络，仅使用 Go 标准库。

## 用法

```sh
go run ./cmd/fragcap [-out datagrams.jsonl] [-summary summary.json] capture.pcap
```

- 数据报 JSONL 写到 `-out`（默认标准输出），每行一个确认完整的数据报：
  `src_ip`、`dst_ip`、`src_port`、`dst_port`、`ident`、`udp_length`、
  `payload_bytes` 及来源记录号 `records`。
- 异常摘要 JSON 写到 `-summary`（默认标准错误），包含记录总数、
  非 UDP 记录数、截断抓取数、按有向五元组（源/目的地址与端口）汇总的
  完整数据报数与 UDP 负载字节数，以及异常列表。

## 输入格式

- 仅支持**经典 PCAP**（版本 2.4），自动识别大端/小端与微秒/纳秒时间戳。
  **不支持 PCAPNG**（魔数不符会直接报错）。
- 仅支持**以太网承载的 IPv4 UDP**。不支持 VLAN、Linux cooked、raw IP
  等其它链路层封装（全局头链路类型非 Ethernet 即拒绝），不支持
  IPv6、TCP 等其它协议（按非目标流量计数后跳过）。
- 校验每条记录的长度字段与抓取截断（`incl_len < orig_len`）；解析以太网
  头长、IPv4 头长（IHL）与总长，并验证 IPv4 头校验和。格式非法的目标
  数据包会以记录号定位后计入异常。

## 重组规则

- 按（源地址、目的地址、协议、标识号）聚合分片，支持乱序到达；
  读完整份文件后才定案，不提前发布。
- 片偏移以 8 字节为单位；非末片（MF=1）负载长度必须是 8 的倍数，
  否则整组判为冲突。
- 末片（MF=0）确定总长后，不接受与之矛盾的末片长度或越界内容。
- 完全相同的重叠字节只计一次；重叠内容不同或末片长度冲突时**整组判为
  冲突**，先到或后到都不覆盖。
- 只有从偏移 0 到末尾无缺口才解码 UDP：UDP 长度字段必须等于重组负载
  长度，且非零校验和必须通过验证（校验和为 0 视为未启用，直接接受）。
- 缺片的组输出缺口字节范围；未见到末片时总长未知，单独标记
  （`last_fragment_unknown`，缺口末端为 -1）。不完整数据**不计入**流量
  统计，重复分片不重复累计。

## 异常类型

| kind | 含义 |
| --- | --- |
| `malformed_packet` | 记录无法按以太网/IPv4 解析（含记录号） |
| `conflict` | 重叠字节不一致、末片长度矛盾或非末片未按 8 字节对齐 |
| `truncated_group` | 组内分片被抓取截断，无法确认完整 |
| `missing_fragments` | 存在缺口（附缺口范围） |
| `last_fragment_unknown` | 未捕获末片，总长未知 |
| `invalid_udp` | UDP 长度不符或校验和验证失败 |
| `read_error` | 读取记录时发生错误（如记录数据截断） |

## 限制

- **标识号复用**：输入假定同一聚合键（源/目的/协议/标识号）在文件内
  只代表一个数据报。若发送方在极短时间内复用同一标识号，两个数据报的
  分片会落入同一组，通常表现为冲突或校验失败而被判为异常，而不会
  被拆成两条流量。
- 不支持 IPv6 分片、PCAPNG、VLAN/QinQ 等封装，也不做实时抓包。
