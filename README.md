# deficit-round-robin-replay

字节赤字轮询（byte-based DRR）回放器：仅使用 Go 标准库，按 CSV 到达事件
重现不同长度分组共享一条输出链路的过程，输出每个分组何时发送或被丢弃。
纯离线模拟，不连接真实网络。

## 构建与运行

```sh
go build .
./drr-replay -flows examples/flows.csv -events examples/events.csv -rate 1000
go test ./...
```

- `-flows`：流配置 CSV，表头后每行 `flow,quantum,wait_limit_bytes`。
  轮询额度与等待字节上限都必须为正。
- `-events`：到达事件 CSV，表头后每行 `time,flow,packet,length_bytes`。
  时间单位秒；分组标识全局唯一；长度为正。
- `-rate`：链路速率（字节/秒），必须为正。

## 事件顺序

1. 到达事件按到达时刻稳定排序，同刻保留输入顺序。
2. 任何调度决策之前，先接纳当前时刻（及之前）的全部到达；发送完成时
   先接纳同刻到达，再继续当前访问。
3. 发送不可抢占，耗时 = 长度 / 链路速率；发送期间的到达照常入队。
4. 所有流空闲时，模拟时间跳到下一个到达时刻，并从最小流标识重新
   开始循环；轮询本身不消耗模拟时间。
5. 输入结束后继续排空已接纳队列，直到全部为空。

## 赤字规则

- 各流按标识字典序循环访问。访问非空队列时只增加一次额度
  （`deficit += quantum`），随后连续发送额度可覆盖的队首分组并扣除其
  字节数；同一次访问不会因新到分组再次增加额度。
- 队首过大时保留余额转向下一流，不能跳过队首挑小包；大包可靠多轮
  积累额度后发送，不会误判为无进展。
- 每次发送完成并处理同刻到达后，队列为空才结束访问并将赤字归零；
  空闲流不积攒额度。
- 等待字节上限只统计尚在排队、未开始发送的分组；超容量仅丢弃新到
  分组并记录原因，不改动已有队列。

## 输出

- **Send timeline**：每个分组的发送起止时刻、所属流与字节数。
- **Drops**：被丢弃分组的时刻与原因（超等待上限或未知流）。
- **Per-flow statistics**：每流到达/接纳/发送/丢弃计数与字节数、平均
  及最大等待时间（发送开始时刻 − 到达时刻）。对账关系：
  `arrived = admitted + dropped`（字节同理），排空后
  `admit_bytes = sent_bytes`。

## 示例走查（examples/，rate=1000 B/s）

`a1`(150B) 首访额度 100 不足，保留余额；`b1`(300B) 一次额度刚好发送
[0, 0.3]；`c3` 在 0.05s 到达时 C 流等待字节将达 180 > 120，被丢弃；
`a1` 第二轮积累到 200 后于 [0.36, 0.51] 发送；2.0s 前所有流空闲，
`a3` 到达后从最小标识 A 重新开始循环。
