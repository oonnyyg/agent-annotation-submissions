# reaction_balance — 反应投料核算工具

仅用 Python 标准库实现的化学计量投料核算工具。先确认每个化学方程式能够**唯一配平**，
再按操作序列逐步核算连续投料与反应后的剩余物料。不计算反应速率，也不计算热力学平衡。

## 运行方式

```sh
python -m reaction_balance input.json [--csv steps.csv] [--json report.json]
```

- 标准输出（或 `--json` 指定文件）为配平结果与逐步库存的 JSON 报告。
- `--csv` 指定逐步物料 CSV 的输出路径。
- 所有反应定义与操作**先全部校验**，校验或配平失败时以退出码 2 报错，
  不写出任何结果文件，不会留下伪完整结果。

## 输入格式

```json
{
  "reactions": [
    {"name": "ammonia", "reactants": ["N2", "H2"], "products": ["NH3"]}
  ],
  "operations": [
    {"type": "add", "species": "N2", "moles": "1.5"},
    {"type": "react", "reaction": "ammonia", "fraction": "0.8"}
  ]
}
```

- `add`：向当前库存加入非负摩尔量的物种。
- `react`：选择已配平反应并给出 0 到 1 的转化比例 `fraction`。
  最大反应进度由当前限制反应物决定（`min(库存/系数)`），实际进度 = `fraction × 最大进度`。
  产物进入库存，可在后续步骤继续参与反应。

## 化学式约定

- 支持元素符号、正整数下标、嵌套圆括号，如 `Ca(OH)2`、`K4(ON(SO3)2)2`。
- 不支持离子电荷、水合物点号、同位素标记。
- 化学式字符串即物种标识；同一方程中物种不得重复。
- 未知元素符号与括号错误会被拒绝。

## 计量假设

- 按元素守恒建立**精确有理数**（`fractions.Fraction`）线性方程组。
- 仅接受零空间维数为 1 且所有物种系数均可取正的配平，结果约成互质正整数。
- 无解与解不唯一是两种不同的错误，分别报告；工具不会自动增删物种或猜测系数。
- 十进制投料量（如 `"0.1"`）按精确十进制值核算，不经过二进制浮点。
- 库存不允许为负；反应进度按上述规则天然保证这一点。
- 每个操作步骤后，校验库存中各元素总量等于累计投料带入量（内部一致性断言）。
- 并列限制反应物（库存/系数 相同且最小）会全部列出。

## 输出精度

- JSON 报告中的摩尔量为**精确值**字符串：整数或 `分子/分母` 形式（如 `"4/3"`）。
- CSV 中的摩尔量为十进制小数，最多保留 10 位小数（四舍五入），仅供查阅；
  精确核算以 JSON 报告为准。

## 测试

```sh
python -m unittest discover -s tests
```

覆盖：括号/嵌套括号配平、不唯一方程的拒绝、产物再次参与反应的链式模拟、
并列限制反应物、十进制精确投料、先校验后执行等。
