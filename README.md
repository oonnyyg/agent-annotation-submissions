# xml-record-splitter

流式 XML 记录拆分工具：按命名空间感知的路径从大型 XML 文档中提取业务记录，
每份记录输出为可独立解析的 XML 文档，并在整个输入校验通过后作为一个新批次发布。
仅使用 Go 标准库。

## 用法

```sh
go run . -path '{urn:env}envelope/{urn:biz}record' -in input.xml -out batch-001 \
    -max-record-size 16777216
```

- `-path`：从文档根开始的绝对路径，逐段为 `{命名空间URI}局部名`；无命名空间的段省略 `{...}`。
- `-in`：输入文件，缺省读取标准输入（按 UTF-8 流式解码，不整读入内存）。
- `-out`：批次输出目录，必须不存在；工具不会覆盖已有目录。
- `-max-record-size`：单条记录序列化后的字节上限（默认 16 MiB，`0` 表示不限），超限即明确失败。

批次目录包含 `record-000001.xml`、`record-000002.xml`……（按原文顺序编号）以及
`index.json`（记录数量、每个文件的大小与 SHA-256 摘要）。

## 匹配语义

- 路径是从根开始的逐段精确匹配，不支持 `//` 之类的模糊后代搜索。
- 同名但命名空间不同的元素严格区分；段内不写 `{uri}` 即只匹配无命名空间元素。
- 记录可以出现在文档任意深度之前提是完整栈与路径一致；匹配按文档顺序依次编号。

## 保真边界

- 保留记录的元素结构、文本、属性值、注释与处理指令；重新解析后名称与文本语义一致。
- 记录根节点补齐其祖先上声明、脱离祖先后仍需使用的全部命名空间声明
  （包括默认命名空间）；记录内部的前缀重绑定按原样保留。
- 不带前缀的属性保持无命名空间，不会错误继承默认命名空间。
- 记录根节点保留生效的 `xml:lang` / `xml:space`，记录内部的覆盖关系不变。
- 不保留原始排版（空白缩进）、前缀拼写或属性顺序；属性值中出现的自定义 QName
  字符串仅按字面文本处理，不做语义解析。
- 字符数据与属性值按 XML 规则转义（含换行/回车/制表符的字符引用），保证往返一致。

## 安全与失败语义

- 拒绝一切 DTD / DOCTYPE 声明，不解析外部实体；未声明的前缀、损坏或截断的 XML
  都会以行列位置报错。
- 记录先写入输出目录旁的临时暂存目录；整个文档通过校验后才重命名为正式批次目录。
  任何错误（包括文档尾部错误）都会清理暂存内容，不留下正式的半批结果。

## 测试

```sh
go test ./...
```

覆盖跨层命名空间声明、默认命名空间与无前缀属性、前缀重绑定、`xml:lang`/`xml:space`
继承与覆盖、DTD 拒绝、未声明前缀定位、截断输入、记录大小上限以及批次发布/清理行为。
