# ogg-packet-audit

纯 Go 标准库实现的 Ogg 容器检查器。它把本地媒体文件拆成可核查的逻辑流
与原始包（packet），导出包数据和 JSON 索引，供归档前检查使用。**不解码
任何音视频内容**，只处理容器结构。

## 运行方式

```sh
go build ./cmd/oggaudit
./oggaudit -out OUTDIR [-max-packet-size N] FILE.ogg
```

- 整个文件校验通过后才会发布结果：输出先写入 `OUTDIR.tmp-<pid>` 暂存目
  录，全部成功后才原子地替换 `OUTDIR`；任何失败都不会覆盖已有成果。
- 输入按页流式读取，整份文件不会一次读入内存；单个包的缓冲受
  `-max-packet-size`（默认 64 MiB）限制，超限即明确失败。
- 退出码：0 表示校验与导出成功；1 表示文件损坏或导出失败；2 表示用法
  错误。所有结构错误都带有文件偏移（`offset N: ...`），程序不会跳过损
  坏页然后假装文件完整。

## 输出布局

```
OUTDIR/
  index.json                    # 包索引（见下）
  stream-000000ab/              # 按逻辑流序号（十六进制）分目录
    packet-000000.bin           # 原始包字节，文件长度即包长度边界
    packet-000001.bin
```

`index.json` 中每个包记录：所属流序号、流内包序号、包文件相对路径、长
度、SHA-256 摘要、**原样保留的颗粒位置**（granule position，不推测播放
时间）、以及该包涉及的每个页的文件偏移与长度。

## 格式说明：分页 ≠ 包边界

Ogg（RFC 3533，版本 0）把数据组织成**页**（page），页是物理封装单位；
**包**（packet）是逻辑数据单位。两者边界一般不一致：

- 每页以捕获标记 `OggS` 开头，含版本（必须为 0）、头类型标志、颗粒位
  置、逻辑流序号、页序号、CRC 和**段表**（segment table，最多 255 项）。
- 段表把页负载切成若干段。段值 255 表示包**继续**；段值小于 255 才表
  示一个包在此**结束**。因此长度为 255 整数倍的包以一个 0 段收尾，空包
  就是一个 0 段。
- 一个包可以跨多页（后续页带 continued 标志），一个页也可以装多个
  包。包边界完全由段表推导，与页边界无关。

本工具执行的校验：

- 捕获标记、版本号、头部长度边界、段表长度；Ogg CRC-32（多项式
  `0x04c11db7`，无反射，初值与末次异或均为 0，CRC 字段自身按零计）。
- 按逻辑流序号分别维护状态：页序号按无符号 32 位递增（允许
  `0xFFFFFFFF` 回绕到 0），漏页、非法重复 BOS 首标记、EOS 结束后的续页
  都会报错。
- 多流交错（multiplexing）：同一组内所有 BOS 页必须先于任何数据页出
  现；前一组所有流都以 EOS 结束后，才允许追加下一组（chaining）。
- 包重组：continued 标志必须与之前未完成的包对应；文件结束不得残留半
  个包，每个流都必须以 EOS 收尾。

## 开发与测试

```sh
go test ./...
```

代码结构：

- `internal/ogg/page.go` — 页解析与 CRC 校验（流式 `Reader`）。
- `internal/ogg/stream.go` — 逐流状态机、分组规则与包重组（`Audit`）。
- `internal/oggxport/export.go` — 包导出、JSON 索引与原子发布。
- `cmd/oggaudit/main.go` — 命令行入口。
