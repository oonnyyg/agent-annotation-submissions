# fractional-lot-cost-basis

本地合成交易记录的批次成本核对工具。按事件顺序回放单币种的买入、
卖出与拆并股，使用精确有理数（`math/big.Rat`）跟踪数量与成本，
全程不使用浮点累计。不连接任何行情或交易平台。

## 输入规则（JSONL）

每行一个 JSON 事件，按文件顺序回放。字段：

- `id`：字符串，全局唯一；重复即拒绝。
- `ts`：ISO 时间戳字符串，不得早于上一个被接受事件的时间。
- `type`：`buy` / `sell` / `split`。
- `qty`：数量，十进制（`"2.5"`）或分数（`"1/3"`）字符串，必须为正。
- `amount_cents` / `fee_cents`：整数分，非负；缺省为 0。
- `method`：卖出分配方式，`fifo`（默认）或 `explicit`。
- `allocations`：`explicit` 卖出必填，`[{"lot":"<buy id>","qty":"..."}]`，
  各分配之和必须精确等于卖出量，同一批次不可重复出现。
- `ratio`：拆并股比例，正数十进制或分数字符串（`"3/2"`、`"0.1"`）。

## 计算规则

- 买入建立独立批次，成本 = 成交总额 + 费用（整数分）。
- 卖出按 FIFO 或显式分配扣减批次。任何校验失败（数量不足、分配之和
  不等、未知批次、费用超过成交额等）都整体拒绝，不做部分扣减；
  被拒绝的事件仍占用事件序号，但不改变状态。
- 部分卖出按批次数量比例消耗成本（`cost * qty / open`）；扣除卖出
  费用后的所得按本次各批次数量占比分摊，逐批计算已实现差额
  （`proceeds_share - cost_out`）。计算中不提前取整，输出精确分数
  （如 `357/4`），保证金额可对账。
- 拆并股以正比例乘全部未关闭批次的剩余数量，总成本与买入次序不变，
  允许分数持仓，不处理零股现金结算；历史卖出与已实现差额不被改写。

## 命令行

```sh
go run . replay examples/events.jsonl      # 回放全部事件并输出最终状态
go run . snapshot examples/events.jsonl 3  # 输出第 3 号事件后的持仓快照
```

快照在独立的账本副本上重放，历史查询不会污染后续回放。输出包括当前
批次明细（数量、剩余成本）及每笔卖出的来源批次、成本、所得与已实现
差额，金额一律以分为单位的整数或精确分数表示。

## 边界

- 仅支持单币种、单资产；多资产请分文件回放。
- 金额以整数分输入，内部分摊可能产生分数分（如 `100/3` 分），输出
  保留精确分数，由调用方决定如何舍入展示。
- 本工具只做数量与成本对账，输出不构成任何税务结论。

## 测试

```sh
go test ./...
```

覆盖：部分卖出后拆股、显式分配不足与求和不符的整体拒绝、分数成本
