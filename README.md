# sqlite-wal-snapshot

离线 SQLite WAL 核验器与快照重建工具。纯 Go 标准库实现，不调用 SQLite
引擎，不修改任何输入文件。

## 用法

```
go run ./cmd/walsnapshot -db main.db -wal main.db-wal [-out snapshot.db]
```

- `-db`：基线主库文件（见下方假设）。
- `-wal`：待核验的 WAL 文件。
- `-out`：可选，重建快照的输出路径。目标文件必须不存在，且不能等于
  `-db` 或 `-wal` 路径（`O_EXCL` 创建，绝不覆盖）。

输出为 stdout 上的 JSON 报告：逐帧记录（页号、偏移、是否提交帧）、有效
前缀长度、最后一次提交帧索引、首个异常的位置与原因、被忽略的尾部字节
范围，以及快照中每一页的来源（`wal` 帧号或 `database`）。

## 基线假设（重要）

输入的主库被约定为**该 WAL 产生之前、尚未回写其中任何页面**的基线。
工具只按字节与校验和核验 WAL 自身的一致性，**无法证明** WAL 与主库
确实配对：WAL 头中的盐值只与帧关联，不与主库文件关联。如果主库已经
回写过 WAL 中的页面，或 WAL 来自另一个数据库，重建结果会静默错误。
请确保 `-db` 是 WAL 产生时刻的主库副本。

## 核验规则

- 校验数据库头（`SQLite format 3`、页大小）与 WAL 头（magic、版本
  3007000、页大小、头校验和），两者页大小必须一致。
- 支持规范的两种校验字节序：magic `0x377f0682`（小端）与
  `0x377f0683`（大端），按 magic 显式选择，绝不使用主机字节序。
- 从文件头开始连续核对每帧的盐值与累积校验和；帧页号必须在
  `1..0xFFFFFFFE`，提交帧声明的库页数不得小于事务内任何页号。
- 遇到坏帧或不完整尾帧立即停止：有效前缀到此为止，绝不跳过错误去
  接纳后面的帧，报告中记录首个异常的字节偏移。

## 快照规则

- 仅帧头中数据库页数字段非零的帧视为提交帧；选择有效前缀中的最后
  一次提交，其后的帧即使校验正确也不进入快照。
- 同一页被多次写入时，以所选提交范围内该页的最后一帧为准。
- 快照按提交帧声明的页数截断或扩展；每页优先取所选 WAL 帧，否则取
  基线主库。两边都缺页时直接报错，不补零。
- WAL 中没有有效提交时，快照为原样基线并在报告中注明；WAL 头非法时
  不生成任何快照。

## 测试

```
go test ./...
```

覆盖：双字节序、同页重复写（最后一帧生效）、未提交尾部排除、坏帧
截断前缀、不完整尾帧、盐值失配、缺页报错、页大小不一致、无提交时
保留基线。
