# HPACK Table Workbench

离线 HPACK（RFC 7541 子集）头部压缩回放工具，仅使用 Go 标准库，不涉及网络收发。
从 JSONL 读取头部列表或十六进制压缩块，逐块输出编解码结果与动态表入表/驱逐记录，
用于观察连续头部块经过编码与解码后字段顺序保持不变、以及压缩表如何随块演化。

## 支持的子集范围

- 四种表示：索引字段（`1xxxxxxx`）、增量索引字面量（`01xxxxxx`）、
  不索引字面量（`0000xxxx`）、永不索引字面量（`0001xxxx`），以及动态表容量更新（`001xxxxx`）。
- RFC 7541 Appendix A 标准静态表；编码器与解码器各自持有独立的动态表。
- 字符串仅支持原始 UTF-8 文本；遇到 Huffman 标志位（H=1）明确拒绝。
- 条目大小 = 名字节数 + 值字节数 + 32；新条目插入表头（索引最小），容量不足时淘汰最旧条目；
  超过容量的条目清空整个表但不入表（RFC 7541 §4.4）。
- 编码策略：精确匹配优先输出索引表示；否则输出增量索引字面量，名称可复用已有索引；
  `sensitive` 字段始终使用永不索引表示，即使表中已有精确匹配也不会泄露为索引引用。
- 容量调整在块之间进行：编码器在下一块开头输出更新；解码器拒绝超过协商上限的更新，
  以及出现在任何字段行之后的更新。容量为零时头部仍可正确编解码（全部走字面量）。

## 错误语义

- 截断整数、越界索引、非法 UTF-8、Huffman 标志等错误都带块号与块内字节偏移。
- 出错的块不输出部分头部；该方向（编码器或解码器）进入失败状态，
  必须显式 `reset` 才能继续；另一方向不受影响。

## 运行

```sh
go run ./cmd/hpacktool [-max-size 4096] [-in input.jsonl] < input.jsonl
```

输入每行一条命令：

```json
{"headers":[{"name":":method","value":"GET"},{"name":"x-token","value":"abc","sensitive":false}]}
{"headers":[...], "table_size":1024}
{"hex":"828684410f7777772e6578616d706c652e636f6d"}
{"table_size":0}
{"reset":"decoder"}
```

- `headers`：编码该头部列表并用配对解码器回放（round trip），输出块十六进制、
  还原后的头部（保持顺序）以及双方的入表/驱逐记录。
- `hex`：仅用解码器解码一个压缩块。
- `table_size`：调整协商容量；编码器在下一块开头输出容量更新。
- `reset`：`encoder` / `decoder` / `both`，清除失败状态。

每行输出一个 JSON 结果：`action`、`block_hex`、`headers`、`table_log`（insert/evict）、`error`。

## 测试与复现

```sh
go test ./...
```

测试覆盖：RFC 7541 Appendix C 官方示例、跨块动态表复用（第二块全索引化）、
敏感字段永不索引、截断整数/越界索引/Huffman/非法 UTF-8 的字节级定位、
失败方向隔离与显式重置、容量更新规则（上限、字段后拒绝、零容量）、驱逐与超大条目清表。
