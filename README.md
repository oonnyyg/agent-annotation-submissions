# ogg-packet-audit

一个基于 Go 标准库的 Ogg 容器检查器（RFC 3533，版本零分页格式）。
它把本地媒体文件拆成可核查的逻辑流与原始包，供归档前检查使用；
**不解码任何音视频内容**。

## 运行方式

```sh
go build ./cmd/oggaudit
oggaudit [-out dir] [-max-packet-size n] [-check-only] <file.ogg>
```

- `-out`：导出目录，默认为 `<file>.audit`。
- `-max-packet-size`：单包长度上限（字节），默认 64 MiB；超限明确失败。
- `-check-only`：只做全文件校验，不导出包文件。

校验全部通过后才会发布导出结果：先写入临时目录，成功后整体替换
输出目录；失败时已有成果保持原样，临时文件被清理。

## 分页与包边界的区别

Ogg 文件由**页（page）**组成，页是物理层单位；**包（packet）**是逻辑
层单位，二者边界通常不重合：

- 每页以捕获标记 `OggS` 开头，含版本号、头类型标志（续包/BOS/EOS）、
  颗粒位置（granule position）、逻辑流序号、页序号、CRC-32 校验和，
  以及最多 255 项的**段表（segment table）**。
- 段表中的每个 lacing 值给出一段长度（0–255）。把页内各段顺序拼接
  即得到包数据流；**lacing 值小于 255 才表示一个包在此结束**。
- 因此：lacing 为 0 产生一个合法的**空包**；长度恰为 255 整数倍的包
  以一个 0 值 lacing 收尾；lacing 为 255 结尾的页表示包延续到下一页，
  下一页必须设置续包（continuation）标志。
- 一个包可以跨越多页，一页也可以装多个包。检查器依据段表重组跨页
  包，不要求页边界与包边界对齐。

## 校验规则

- 逐页校验捕获标记、版本号（必须为 0）、头部长度、段表与段数据
  完整性，并验证 Ogg 使用的 CRC-32（多项式 0x04c11db7，初值 0）。
  所有错误都带有**文件偏移**，损坏即失败，绝不跳过坏页假装完整。
- 按逻辑流序号分别维护页序列：页序号按无符号 32 位递增（允许
  回绕），漏页、非法重复 BOS、EOS 之后的续页都会被识别。
- 支持多流交错（复用）以及前一组结束后追加下一组（链式流，
  同一序号以新的 BOS 页重新开始）。
- 文件结束时任何流不得残留半个包，且每个流都必须有 EOS 页。
- 颗粒位置**原样保留**，不推测播放时间。

## 导出结果

```
<out>/
  index.json
  stream-<序号hex>-g<组号>/
    packet-000000.bin
    packet-000001.bin
    ...
```

`index.json` 记录每个包的长度、SHA-256 摘要、原始颗粒位置，以及
涉及页的文件偏移、长度和页序号，例如：

```json
{
  "source": "in.ogg",
  "size": 12345,
  "streams": [
    {
      "serial": 42,
      "group": 0,
      "packets": [
        {
          "index": 0,
          "file": "stream-0000002a-g0/packet-000000.bin",
          "length": 6,
          "sha256": "…",
          "granule": 0,
          "pages": [{"offset": 0, "length": 34, "sequence": 0}]
        }
      ]
    }
  ]
}
```

包数据通过回调流式写出，整份输入不会被一次读入内存。

## 测试

```sh
go test ./...
```

测试使用合成的 Ogg 夹具，覆盖：合法单流/多流交错/链式组、空包与
255 整数倍包、跨页包重组、CRC 损坏、捕获标记错误、截断页、页序号
缺口与回绕、重复 BOS、EOS 后续页、续包标志不匹配、文件结束残留
半包、单包长度上限，以及"失败不覆盖已有导出"。
