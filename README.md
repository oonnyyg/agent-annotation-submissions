# transit-fare-capping

本地公共交通计价工具：换乘优惠与日/周封顶串联计费，支持撤销乘车记录后整卡重新核对。
仅使用 Go 标准库，所有金额均为整数分（integer cents）。

## 运行

```sh
go run ./cmd/farecap -config examples/config.json -input examples/events.jsonl -state farecap-state.json
```

- `-config`：JSON 费率配置路径（默认 `config.json`）。
- `-input`：JSONL 记录文件；省略或 `-` 表示从标准输入读取。
- `-state`：状态持久化路径（默认 `farecap-state.json`），每次运行后原子写入。
- `-query`：不导入数据，只加载已有状态并输出当前各卡账单。

输出为单个 JSON 对象到标准输出，包含：

- `events`：每行输入的处理结果（`accepted` / `duplicate` / `rejected` / `revoked` 及原因）。
- `results`：每张卡重算后的日账单、周账单、逐趟扣费与累计金额。
- `revocations`：完整撤销历史，撤销不会删除审计记录。

## 费率配置（自定义规则）

见 `examples/config.json`：

- `utc_offset_seconds`：固定 UTC 偏移（秒），用固定偏移时区，**不引入夏令时**。
- `service_day_start_hour`：服务日起始本地小时（0-23）。例如 4 表示凌晨 4 点，
  本地 03:30 的乘车属于前一个服务日。
- `transfer_window_seconds`：换乘时限（秒）。后续上车时间距**当前换乘组首趟上车**
  严格小于该值（`<`，不等于）才并入同一组；窗口不会因每次换乘而滚动延长。
- `fares`：按覆盖区间宽度 `width = max(所有起终区号)-min(...)+1` 索引的票价表，
  必须按宽度单调非降，宽度不可重复。缺少所需宽度时该记录/操作被拒绝。
- `daily_cap` / `weekly_cap`：非负日、周上限（分），且 `weekly_cap >= daily_cap`。

服务周从**周一服务日起点**（周一凌晨 4 点本地时间）开始。

## 记录格式（JSONL，每行一条）

乘车：

```json
{"id":"r2","type":"ride","card":"card-001","board":"2026-10-05T09:00:00+08:00","alight":"2026-10-05T09:20:00+08:00","from_zone":1,"to_zone":3}
```

撤销：

```json
{"id":"v1","type":"revoke","card":"card-002","target_id":"r3"}
```

- 时间接受 RFC3339（带偏移，内部统一为 UTC 时刻）或不带时区的
  `2006-01-02T15:04:05`（按配置的固定偏移解释）。
- 区号为连续正整数；`alight` 不得早于 `board`。

## 处理规则

1. 记录按**上车时间，再按记录编号**排序。
2. 同一张卡的行程时间区间为半开区间：端点相接（前车下车 == 后车上车）允许，
   区间重叠则拒绝新记录。
3. 相同编号 + 完全相同内容重提：记为 `duplicate`，不重复计费；
   相同编号但内容冲突：`rejected`，旧记录保持不变。
4. 同服务日内、换乘窗口内的后续乘车并入同一换乘组；跨服务日必定另开新组，
   不沿用昨日窗口。
5. 组票价按组内全部起终区号的 `max-min+1` 查票价表。每趟增量 =
   并入后的新组票价 - 该组此前已扣费；再被 `日剩余额度` 与 `周剩余额度`
   的最小值限制（实际扣费 = min(增量, 日剩余, 周剩余)，下限 0），
   实际扣费同时累计到日、周两级封顶。
6. 撤销：从有效记录中移除目标乘车（卡号必须匹配），保留撤销历史，
   然后对该卡的全部有效记录**从头完整重算**，而不是直接退回旧扣费——
   因此换乘分组、组票价与两级封顶都会重新核对。

## 状态与查询

状态文件保存全部有效乘车与撤销历史（见 `-state`）。账单总是从有效记录
确定性重算，所以：

- 进程正常重开后结果一致（有回归测试覆盖）；
- 重放同一批输入只会得到 `duplicate`，不会重复计费；
- 任何时候用 `-query` 即可查看当前日/周账单与逐趟扣费。
