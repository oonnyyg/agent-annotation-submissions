# 集选电梯离线调度回放器

仅用 Go 标准库实现的单台电梯集选（collective control）运行回放器。
读取 JSON 楼层参数与乘客到达记录，输出逐事件日志与每位乘客的行程，
用于分析乘客等待时间与满载滞留，不控制任何真实设备。

## 运行

```sh
go run . input.json        # 从文件读取
go run . < input.json      # 或从标准输入读取
go test ./...              # 运行测试
```

## 输入格式

```json
{
  "config": {
    "minFloor": 1,
    "maxFloor": 10,
    "initialFloor": 1,
    "capacity": 2,
    "travelTimePerFloor": 2,
    "stopTime": 3
  },
  "passengers": [
    {"id": "a", "arriveTime": 0, "from": 1, "to": 5}
  ]
}
```

- 配置：`minFloor < maxFloor`，`initialFloor` 在范围内，`capacity`、
  `travelTimePerFloor`、`stopTime` 均为正整数。
- 乘客：`id` 唯一非空，`arriveTime >= 0`，`from`/`to` 在楼层范围内且不同。
- 任何一条记录非法则整体拒绝，退出码非零，不产生回放输出。

## 调度规则

- 空闲时选择最早等待者（同刻按输入次序），空载直达其起点后采用其出行方向。
- 沿当前方向，前方还有车内目的地或任意等待起点时继续前行，否则在停靠点反向；
  不在楼层之间改向。
- 到站先下客，再按等待次序接纳同方向乘客；满载时多余乘客保留等待（计为滞留）。
- 仅有下客或可接纳乘客时才停靠开门；反向后可在当前层接客。
- 车内目的地不因外部新请求而丢失。

## 事件次序

同一时刻的处理顺序固定为：

1. 登记该时刻新到达的乘客（同刻按输入次序）；
2. 处理电梯到站（下客）；
3. 方向决策（必要时反向）；
4. 开门瞬间上客（仅这一瞬间，停靠期间新到者等待下一次机会）。

无停靠时只计每层运行耗时 `travelTimePerFloor`；停靠额外计 `stopTime`。
全部乘客完成行程后停止推进。

## 输出

- `== 事件日志 ==`：逐事件时间线（到达、上下车、反向、停靠、空闲、满载滞留）。
- `== 乘客行程 ==`：每位乘客的到达、上车、下车时刻与等待时间。
- `== 运行汇总 ==`：完成时刻、最大载客、满载滞留人次、总/平均/最大等待。

任意时刻载客不超过 `capacity`，每位乘客只完成一次行程（由测试保证）。

## 复现方法

回放是确定性的：相同输入必然产生相同输出。

```sh
go run . input.json > out1.txt
go run . input.json > out2.txt
fc out1.txt out2.txt   # Windows；Unix 用 diff
```

测试覆盖端点反向、满载滞留、同刻到达次序与非法输入拒绝：

```sh
go test ./... -v
```
