# project-crash-planner

用 Go 标准库实现的关键路径 (CPM) 与工期压缩 (crashing) 分析工具。纯离线计算,
不执行真实任务, 也不对接任何项目管理平台。

## 输入

JSON 文件描述非空活动集合 (参见 `examples/project.json`):

```json
{
  "budget": 8,
  "activities": [
    {"id": "design", "duration": 4, "predecessors": [], "crash": {"duration": 2, "cost": 5}}
  ]
}
```

- `duration`: 非负整数天, 允许零工期里程碑。
- `predecessors`: 完成后才能开始的依赖列表。标识必须唯一; 未知依赖、自依赖与环会被拒绝。
- `crash` (可选): 更短的非负工期与正整数成本, 每项只能选或不选。可压缩活动至多 18 项。
- `budget`: 非负整数。

所有无前置活动从第零天开始; 不考虑人员限制与工作日历。

## 用法

```sh
go run . -input examples/project.json -csv-prefix out/schedule -json out/report.json
```

- 标准输出: 基准与方案的摘要 (完工日、关键路径、关键活动)。
- `-csv-prefix`: 写出 `<prefix>_baseline.csv` 与 `<prefix>_plan.csv` 两张计划表
  (id, duration, crashed, es, ef, ls, lf, float, critical)。
- `-json`: 写出完整选择理由 JSON (基准与方案对照、逐活动时差、关键路径、rationale 文本);
  省略时打印到标准输出。

## 计算方法

- 前推计算最早起止 (ES/EF) 与项目完工日; 所有活动共用同一完工日后推最晚起止
  (LS/LF) 与总时差, 因此并行的独立分支不会各自声称零时差。
- 关键路径沿真实依赖边从起点延伸到终点 (无关键后继的末端关键活动); 多条候选时
  取活动标识序列字典序最小者, 而不是把所有零时差活动拼在一起。
- 压缩选择为全局精确搜索: 枚举至多 2^18 = 262144 个子集, 在预算内取整体完工日最早者;
  同完工日先比总成本, 再比排序后的已选标识序列。不以单项收益贪心代替全局选择。
- 压缩后重新计算全部时差与关键路径, 关键路径可能转移到原先有时差的分支。

## 计算规模

- CPM 前推/后推: O(V + E)。
- 压缩搜索: O(2^n * (V + E)), n 为可压缩活动数 (n <= 18), 每次枚举约数十万级,
  秒级完成。若 n 更大, 此穷举不再适用, 需改用分支限界或整数规划。

## 不包含的约束

本工具只做时间-成本权衡, 明确不建模: 人员/资源限制、工作日历与非工作日、
部分压缩 (连续 crashing 曲线)、多方案互斥以外的复杂约束、真实任务执行与项目平台对接。

## 测试

```sh
go test ./...
```

覆盖: 并行关键分支共享完工日、零工期里程碑、字典序最小关键路径、预算约束、
同完工日的成本与标识平局、压缩后关键路径转移、未知依赖/环/重复标识的拒绝。
