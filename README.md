# Blocking Workshop Replay

本地车间回放工具：按离散事件重演工单在工位间的流转，解释工单为何
等待（排队）或占机阻塞（blocked），并区分「真正完成」与「没有事件
可推进」的停滞（stall）状态。不追求最优排程，只按固定规则回放。

## 运行

```sh
go run ./cmd/workshop -input examples/blocking.json -csv ops.csv -summary summary.json
```

- `-input`：工位与工单 JSON（必填）。
- `-csv`：工序时间 CSV 输出路径（缺省标准输出）。
- `-summary`：状态摘要 JSON 输出路径（缺省标准输出）。
- 全部完成时退出码 0；发生停滞时退出码 1 并在 stderr 提示；输入非法时退出码 2。

## 输入格式

```json
{
  "stations": [{"id": "S1", "buffer": 0}],
  "jobs": [{"id": "J1", "release": 0,
            "route": [{"station": "S1", "duration": 2}]}]
}
```

- 每工位一台机器；`buffer` 为等待缓冲容量，非负整数，**不含**机器上
  的加工件。
- 每工单有非负释放时刻 `release` 和有限的工序序列 `route`，可重复
  访问同一工位；`duration` 必须为正整数。
- 未知工位、重复工位编号、重复工单编号、空路线、负释放时刻、非正
  时长都会被拒绝。所有编号比较均按字典序。

## 事件顺序

仿真按离散事件推进（释放与加工完成），不逐时间单位轮询。每个时刻
的处理顺序为：

1. **登记**：先登记该时刻的全部释放与完成事件。末工序完成的工单
   立即离开并释放机器；非末工序完成但下站无法接收的工件留在原机
   上进入占机阻塞状态（不释放机器，后续工件不能提前开工）。
2. **转移**：按工单编号字典序，反复尝试可行转移——外部等待的工单
   进入首站，阻塞工件移往下站。缓冲有空位即可入队；零容量只能在
   机器空闲时直接交接上机。机器空闲且队列为空时直接上机，否则按
   「入队时刻、工单编号」排序入队。转移失败不丢件；由于接收方必须
   真的有空位或空闲机器，阻塞机器之间无法循环互换绕过容量。
3. **开工**：按工位编号字典序，空闲机器从队列头部取件开工。
4. 重复 2–3 直到本时刻无变化，再推进到下一事件时刻。

## 统计边界

CSV 每行对应一道工序：`arrive`（开始等待该站的时刻，首工序为释放
时刻，其余为转入时刻）、`start`、`end`、`leave`（离开机器时刻）及
三段分解：

- `queue = start - arrive`：排队时长（含首工序在外部等待的时间）。
- `process = end - start`：加工时长。
- `blocked_after = leave - end`：完成后因下站无法接收而占机阻塞的
  时长；末工序恒为 0。

摘要 JSON 按工单累计这三类时长。若仍有未完成工单但既无未来事件也
无可行转移，则报告 `stalled: true`、`stall_time` 以及此刻的占用关
系（`occupancy` 机器被谁占用、`queues` 各站队列、`external` 站外
等待）；停滞时仍占机阻塞的工序按 `stall_time` 结算其 CSV 记录。
