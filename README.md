# ruleaudit — 决策表上线前静态分析器

`ruleaudit` 读取 JSON 描述的字段域与**有序规则**，在上线前精确找出：

- **遗漏输入**：未被任何规则覆盖的区域（含可直接复现的最小见证输入）；
- **互相遮蔽/冲突的规则**：多条规则同时命中的区域；
- **被联合遮蔽的规则**（首条命中策略）：被前面**多条规则联合**完全覆盖、永远不会生效的规则。

分析基于**等价单元穷举**而非随机采样：按所有规则边界把每个字段域划分成原子段，
每个单元内所有输入的规则匹配结果完全相同，因此结论是精确的。

## 运行

```sh
go run ./cmd/ruleaudit -spec examples/shadowed.json -strategy first
go run ./cmd/ruleaudit -spec spec.json -strategy unique -input '{"tier":"pro","age":30}'
```

参数：

- `-spec <path>`：规格文件，缺省读标准输入；
- `-strategy unique|first`：命中策略，默认 `unique`；
- `-max-cells N`：等价单元总数上限，默认 100000，`0` 表示不限；
- `-input '<json>'`：可选，对单个样本输入求值。

退出码：`0` 无诊断；`1` 存在遗漏/重叠/遮蔽；`2` 规格或参数错误；`3` 单元超限、分析未完成。

## 规则格式

```json
{
  "fields": [
    { "name": "tier", "type": "enum", "values": ["free", "pro", "enterprise"] },
    { "name": "age",  "type": "int",  "min": 0, "max": 120 }
  ],
  "rules": [
    { "name": "adults-pro",
      "when": { "tier": ["pro"], "age": { "min": 18, "max": 65, "maxExclusive": true } },
      "output": "standard" }
  ]
}
```

- 字段只支持**有限枚举**（`enum`，`values` 为声明顺序）和**有界整数**（`int`，含 `min`/`max`）。
- 规则是各字段条件的**合取**；省略某字段表示该字段不限。
- 枚举条件：值集合，可简写为数组 `"tier": ["pro"]`，或对象形式 `{"values": [...]}`。
- 整数条件：区间对象 `{"min":..,"max":..,"minExclusive":..,"maxExclusive":..}`，
  端点默认闭区间，`Exclusive` 置真为开端点；省略某一端表示沿域边界不限。
- 校验拒绝：未知字段、未知枚举值、域外区间端点、类型不匹配的条件；
  **空条件区间**会定位到具体规则序号报错（如 `rule 1: field "x": empty condition interval`）。
- 分析器只做静态匹配，**不执行任何外部表达式**。

## 命中策略

- `unique`（唯一命中）：每个输入必须恰好命中一条规则；多条命中即冲突，
  **即使输出相同也不通过**。
- `first`（首条命中）：返回最早命中的规则，但诊断与样本求值都会保留**全部**匹配记录；
  同时识别被前面若干规则**联合**完全遮蔽的规则，并为仍可生效的规则给出见证输入。

## 见证顺序

所有反例/见证取**最小输入**：按字段声明顺序逐字段取最小，
枚举按声明顺序、整数按数值顺序。例如字段顺序为 `(tier, age)` 时，
`{tier=free, age=0}` 先于 `{tier=free, age=1}` 与 `{tier=pro, age=0}`。
区间单元的代表元取其最小值（枚举取组内首个声明值，整数取下界）。

## 规模限制

单元总数为各字段原子段数的乘积。整数域的原子段由所有规则边界切分，
枚举域按“在规则集合中的成员关系”等价类合并。若单元总数超过 `-max-cells`，
工具明确报告 `INCOMPLETE` 并以退出码 3 结束，**不会给出无冲突结论**。

## 样本求值一致性

`-input` 的样本求值与静态分析共用同一匹配器：静态报告中的每个见证输入，
求值结果与静态结论必然一致（由 `TestEvalConsistency` 保证）。
