# incremental-build-runner

一个小型本地构建器（仅 Go 标准库，无后台服务）：按依赖顺序执行目标命令，
并基于**内容指纹**复用未变化的结果。每次运行都会给出明确的重建 / 跳过原因。

## 清单格式（build.json）

```json
{
  "targets": {
    "gen": {
      "deps": [],
      "command": ["tool", "--flag", "arg"],
      "inputs": ["src/in.txt"],
      "outputs": ["out/mid.txt"]
    },
    "pack": {
      "deps": ["gen"],
      "command": ["tool", "pack"],
      "inputs": ["out/mid.txt"],
      "outputs": ["out/final.txt"]
    }
  }
}
```

- `command` 是参数数组，直接 `exec` 启动，**不经过 shell**，工作目录固定为工作根。
- `inputs` / `outputs` 必须显式声明，且都是工作根内的相对路径。

## 运行

```sh
go build -o builder .
./builder -manifest build.json -root . [目标名...]
```

选项：`-cache`（缓存目录，默认 `.buildcache`）、`-logs`（逐目标日志目录，
默认 `build-logs`）、`-report`（JSON 报告路径，默认 `report.json`）、
`-plan`（只预览计划，不执行命令、不改缓存）。
不指定目标时构建全部目标；指定时仅执行其依赖闭包。

## 运行边界与保证

- **路径安全**：所有输入 / 输出必须是工作根内的相对路径；拒绝绝对路径、
  `..` 越界路径以及路径中任何符号链接。命令本身在工作根内执行，但构建器
  无法阻止恶意命令自己越界写文件——清单即信任边界。
- **图校验先于执行**：未知依赖、依赖环、输出被多个目标重复声明、读取其他
  目标的输出却未声明依赖，都会在运行任何命令之前整体拒绝。
- **执行顺序**：依赖先于使用者；无依赖关系的目标按名称字典序。
- **缓存指纹**：SHA-256 覆盖命令参数、输入文件内容、直接依赖的输出内容，
  与修改时间无关。命中缓存还要求本目标输出存在且内容哈希与记录一致
  （检测外部篡改）；把文件改回原内容不会仅因时间戳变化而重建。
- **失败语义**：非零退出或缺少声明输出即失败，不写入成功缓存；依赖失败的
  目标标记 `skipped` 并注明原因，无关分支继续执行。
- **计划预览**：`-plan` 下若上游将重建，下游标记 `pending-upstream`，
  因为新输出指纹只有真正执行后才能知道。
- **持久化**：缓存写入本地 JSON 文件（原子替换），重启后可复用。

## 报告与日志

JSON 报告中每个目标的状态为 `cached` / `rebuilt` / `failed` / `skipped`
（计划模式为 `cached` / `rebuild` / `pending-upstream`），并附人类可读的原因。
每个目标的 stdout/stderr 写入 `build-logs/<目标名>.log`。

## 测试

```sh
go test ./...
```

覆盖：内容失效与内容恢复、输出外部篡改、分支失败与跳过、计划预览、
图校验（环 / 未知目标 / 越界路径 / 符号链接 / 输出归属 / 未声明依赖）。
